# 管网科技情报与科研辅助平台功能开发范围与逐项确认

版本 V0.1　日期 2026年10月12日　用途 开发范围讨论与需求确认

本次讨论需要确定系统服务对象、具体业务功能、交付深度、优先顺序和验收方法。本文列出建议开发内容和待决策事项，供业务负责人、领导和研发人员逐项确认。任何功能只有形成明确会议结论后，才进入正式开发范围；本文件不代表这些功能已经完成，也不替代合同约定。

建议先确认第1至4章的定位、职责和业务流程，再按第5至16章逐项核对功能。第17章讨论可选扩展，第18章确定质量和运行指标，第19章确定分阶段交付，第20至22章用于现场验证、记录决策和冻结需求。

## 1 讨论方法与确认规则

### 1.1 每项功能需要形成的结论

不要只确认“有无这个功能”。每项至少确认使用者、业务目的、输入材料、处理方式、输出结果、权限、异常处理和验收证据。功能说明中的“建议一期”“建议二期”“可选”均是供讨论的安排，不代表已获批准。

每项功能统一记录：确认结果〔保留／调整／暂缓／不做／待补材料〕；交付阶段〔一期／二期／其他〕；业务确认人；需要调整的细节。未明确分期的功能不自动进入一期，未提供材料的功能不默认允许研发自行编造业务规则。

“保留”表示认可功能方向；只有字段、规则、样例、权限和验收标准也确认后，才具备拆分开发任务的条件。安全和权限基础要求不能因为某个业务功能暂缓就被取消。

### 1.2 建议参会职责

| 参与方 | 本次需要确认的内容 |
| --- | --- |
| 业务负责人或领导 | 业务目标、范围取舍、正式成果定义、优先级及验收负责人 |
| 情报业务人员 | 来源清单、技术分类、过滤与重要性规则、简报栏目和样例 |
| 科研业务人员 | 三类材料的用途、正式模板、字段、指标和经费规则 |
| 审核人员 | 内容审核、成果审核、退回、发布以及责任边界 |
| 数据与系统管理人员 | 账号、权限、数据安全、运行环境、备份和日常维护 |
| 研发与测试人员 | 可实现边界、依赖、任务拆分、验证方法和风险，不替业务方决定专业结论 |

### 1.3 本轮建议的讨论顺序

先确定主业务和首批真实样例，再确认数据接入与处理、阅读检索、科研编制、简报、审批发布和管理配置。最后讨论图形深度、可选扩展、性能容量和排期。避免在未明确业务之前只讨论页面颜色或按钮位置。

每次会议可以只确认一组模块。记录具体功能编号，例如“F05相关性过滤保留，阈值由情报负责人提供”，不要只写“数据处理没问题”。

## 2 系统定位与范围边界

### 2.1 建议定位

系统面向管网科技情报和科研业务，统一整理外部资讯、论文元数据与内部资料，支持查找、审核、引用和成果编制。AI用于过滤、摘要和辅助写作，正式事实、技术指标及对外成果由人员复核。

主业务有两条：情报业务从数据接入走到可信情报库与简报；科研业务从授权资料走到科研材料草稿、复核和正式输出。可以共用资料、模型和权限基础能力，但不应混成一个无法区分任务目的的页面。

### 2.2 已明确的项目约束

| 事项 | 本次讨论采用的边界 |
| --- | --- |
| 知识问答 | 已要求移除，不重新作为默认开发功能；保留资料库不等于恢复问答 |
| Kafka Dashboard | 已要求移除，不作为系统运行管理页面 |
| 登录界面 | 保留既有视觉，不因内容区优化另行重做登录封面 |
| 数据库方向 | 统一PostgreSQL，已融合的数据处理能力作为同一项目组成部分 |
| InsightHub | 作为后台数据处理能力，不要求普通用户理解或操作独立产品 |
| DeepSeek | 可作为模型接入方向；模型选择不替代权限、内容质量和数据外发确认 |
| 本次工作 | 明确需求和开发范围，不按本稿自动执行代码开发、部署或业务操作 |

以上为已有明确方向，若会议要改变，应记录变更原因和影响。旧规格中的知识问答、旧时间表或“全部P0”清单，不自动覆盖后续决定。

### 2.3 不应默认承诺的能力

不默认承诺全部网站通用采集、受限论文全文获取、模型输出直接报批、无证据的指标与经费生成、无人审核自动对外发布、自动训练模型、全组织协同办公或集团统一身份对接。这些内容如确有需要，应单独明确范围、负责人、依赖和验收样例。

### 2.4 系统边界

爬虫脚本与平台接入分开验收：爬虫方负责明确来源的采集与合法可用数据，平台负责接收、校验、处理、审核和使用。某个来源脚本尚未提供，不应阻止平台用授权样本联调；平台能接收样本也不代表该来源爬虫已交付。

平台不替代项目立项、预算审批、科研管理或OA系统。若需要与这些系统交换数据，应另列接口和字段，不把“导出Word”当成已经完成系统对接。

## 3 使用角色与权限原则

### 3.1 建议角色

| 角色 | 职责 | 默认不得拥有的能力 |
| --- | --- | --- |
| 普通业务人员 | 检索阅读、收藏、管理本人资料、编制本人报告和简报 | 修改全局规则、查看他人私密资料、正式发布 |
| 情报维护人员 | 维护来源、复核处理结果、修正信息、审核情报入库 | 默认读取所有人的私有科研报告 |
| 科研编制人员 | 使用授权资料、编制和修改科研材料 | 冒充业务审核人完成审核 |
| 业务审核人员 | 审核被分配成果、提出意见、通过或退回 | 不受约束地查看全部私有资料 |
| 模板与模型配置人员 | 管理获授权模板、提示词、模型和测试 | 默认读取全部业务正文或获取明文密钥 |
| 系统管理员 | 账号权限、运行配置、日志和维护 | 仅凭技术管理员身份自动获得业务审批资格 |

角色可以兼任，但技术权限与业务职责应分别确认。小规模试点可由同一人兼任审核和情报维护，仍需保留操作身份及记录。

### 3.2 数据访问规则

建议一期至少明确“本人私有”和“平台授权公开”两类。部门、项目组、逐人共享是否一期开发，需要单独确认；不能只增加一个下拉选项而没有实际授权规则。

查看、下载、复制、用于AI、修改、删除和发布不是同一权限。搜索结果、正文片段、任务、版本、图形、导出文件都必须遵守同一资料范围。已知资源ID或文件路径不应绕过权限。

资料被撤回、删除或收回授权后，需要区分“禁止再次生成”和“历史报告如何保存”。建议历史成果保留生成时证据版本和引用关系，原文访问仍重新校验；是否需要脱敏、撤回或删除历史产物，由数据管理政策确认。

### 3.3 权限矩阵讨论项

| 操作 | 普通编制人员 | 情报维护人员 | 业务审核人员 | 系统管理员 |
| --- | --- | --- | --- | --- |
| 阅读正式公共情报 | 允许 | 允许 | 允许 | 按授权 |
| 管理本人私有资料 | 允许 | 本人范围 | 本人范围 | 不默认读取正文 |
| 审核公共情报 | 不允许 | 按授权 | 按授权 | 需另授业务权限 |
| 编制报告与简报 | 本人或获授权 | 本人或获授权 | 本人或获授权 | 需另授业务权限 |
| 审核他人成果 | 不默认允许 | 不默认允许 | 被分配范围 | 需另授业务权限 |
| 正式发布 | 不允许 | 需另授权 | 按发布规则 | 需另授业务权限 |
| 配置账号与模型 | 不允许 | 仅获授权部分 | 不默认允许 | 按职责授权 |

本表是建议权限方案，所有角色名称和职责仍需会议确认，不是当前系统已经具备的完整权限矩阵。

## 4 主业务流程与状态

### 4.1 外部情报流程

登记来源 → 试采确认 → 接收原始数据 → 清洗去重 → 相关性过滤 → 摘要分类评分 → 人工复核 → 审核通过 → 用户检索阅读 → 引用于简报或科研材料。

建议将处理状态与审核状态分开。采集成功不等于处理成功，处理成功不等于允许展示；过滤拒绝不一定是系统故障。人工修改后的正式目录字段应与前台展示一致，不能只把新结果保存到用户看不到的处理快照。

### 4.2 内部资料流程

上传并选择权限 → 文件安全检查 → 文本解析 → 结果预览和纠错 → 可用性确认 → 检索或加入资料篮 → 授权用于生成。

扫描通过不等于解析成功，解析成功不等于完成语义索引。处理失败应允许补充资料或重试，不使用“已上传”替代“可用于生成”。

### 4.3 科研成果流程

选择材料类型和模板 → 填写业务需求 → 选择证据 → 确认大纲 → 后台生成草稿 → 编辑与核对引用 → 规则检查 → 人工复核 → 定稿 → 按需提交审核 → 正式发布或导出归档。

“任务执行完成”“作者定稿”“审核通过”“正式发布”需要分别定义。若一期只做作者定稿，不开发多人审批，应明确说明，不能通过一个“已完成”状态掩盖差异。

### 4.4 简报流程

选择周期和方向 → 检索候选 → 去重与选题 → 确认栏目 → 生成草稿 → 人工调整 → 来源核对 → 定稿与审核 → 导出或发布。自动计划只替代周期派发，不自动获得发布权限。

### 4.5 建议状态与允许动作

| 对象 | 建议状态 | 关键动作与限制 |
| --- | --- | --- |
| 采集运行 | 排队、运行、成功、部分成功、失败、取消 | 失败可重跑，运行中取消需要说明停止边界 |
| 内容处理 | 待处理、处理中、保留、过滤拒绝、失败 | 拒绝说明原因，失败允许有限重试 |
| 内容审核 | 待审、通过、拒绝、撤回 | 普通用户仅见满足展示条件的内容 |
| 文件 | 待扫描、隔离、待解析、解析中、可用、失败 | 未就绪文件不能用于AI |
| 生成任务 | 排队、执行、取消、失败、完成 | 完成只表明产出草稿，不代表批准 |
| 成果 | 草稿、待复核、定稿、待审核、退回、通过、已发布、归档 | 多人审核是否启用由会议决定；修改内容使旧复核失效 |
| 导出任务 | 排队、执行、完成、失败、过期 | 完成后提供受控下载，失效文件可重新生成 |

## 5 门户与个人工作区

### P01 账号登录与会话管理

- 建议阶段：一期基础。使用者：全部授权人员。
- 输入与操作：账号、密码、按策略验证码；登录、退出、会话失效处理、返回原目标页。
- 输出与规则：进入获授权业务区域；退出清除个人状态。保留现有登录视觉，普通用户不进入管理侧栏。
- 异常与权限：密码错误、锁定、失效会话有可恢复提示；不得泄漏他人任务或资料。
- 验收：A退出后B登录，收藏、资料篮、任务和编辑状态无串号；原受保护链接登录后可正确返回。
- 待确认：账号由管理员开通还是开放注册；是否允许多端登录；锁定与超时策略。确认记录：________。

### P02 首页与业务导航

- 建议阶段：一期。使用者：普通业务人员。
- 输入与操作：进入首页，查看近期情报、论文、本人待办、任务和最近成果；进入对应业务页。
- 输出与规则：统计来自真实授权数据；任务与资讯分区，避免首页变成后台监控面板。
- 异常与权限：无数据、加载失败、无权限分别提示；不以默认案例充当业务数据。
- 验收：每个入口能完成对应动作；首页显示数量与实际记录一致，窄屏和侧栏变化不遮挡操作。
- 待确认：首页最重要的三项信息，是否展示公共成果和运营统计。确认记录：________。

### P03 统一检索

- 建议阶段：一期关键词检索，语义检索另见E01。使用者：全部获授权人员。
- 输入与操作：关键词、内容类型、时间、方向、来源、可见范围；筛选、排序、分页和清空。
- 输出与规则：结果区分资讯、论文、内部资料、成果，显示命中字段与来源；只返回有权内容。
- 异常与权限：无结果给出调整条件建议，接口错误不显示成零条；索引延迟需提示。
- 验收：用已知标题、DOI、正文关键词核对检索；私有文件标题与片段都不泄漏给B。
- 待确认：检索字段、排序优先级、是否需要复杂组合条件和保存检索方案。确认记录：________。

### P04 收藏与资料篮

- 建议阶段：一期。使用者：编制人员。
- 输入与操作：从资讯、论文、内部资料添加或移除条目，查看来源与可用状态，再用于指定任务。
- 输出与规则：收藏用于个人阅读；资料篮用于本次或后续编制，二者不等同；跨页选择仍保留正确类型。
- 异常与权限：资料删除、撤回或失去权限时标明不可用；移除不删除原始资料。
- 验收：搜索结果和第二页条目加入后刷新仍在，进入任务时再校验权限，不能把论文误当上传资料。
- 待确认：资料篮是否按项目分组、是否设条数上限、是否允许团队共享。确认记录：________。

### P05 我的任务与成果

- 建议阶段：一期。使用者：编制人员。
- 输入与操作：按类型、状态、时间查询本人任务和成果，查看进度、错误、重试、复制配置、继续编辑。
- 输出与规则：区分科研、简报、解析、导出等任务；如果一期仅覆盖部分，必须在名称中明确。
- 异常与权限：失败保留错误原因与操作入口，离开浏览器不取消后台任务，运行中重复重试受限制。
- 验收：关闭页面后重新进入仍能找到任务；不同类型正确进入各自编辑器，任务完成不被显示成审核通过。
- 待确认：是否一期统一全部任务、历史保留周期、复制与重试的覆盖行为。确认记录：________。

### P06 个人资料与消息提醒

- 建议阶段：个人资料一期，完整消息中心可二期。使用者：全部人员。
- 输入与操作：维护允许修改的个人资料和密码；查看任务完成、失败、审核退回等提醒。
- 输出与规则：账号、角色等敏感身份由管理员维护；消息能跳到实际对象，已读状态明确。
- 异常与权限：原对象失效时提示；密码恢复与任务提醒不是同一功能，不能混为“通知”。
- 验收：用户只能改本人允许字段；启用的提醒确实送达对应人员，不因刷新重复发送。
- 待确认：一期只做页面反馈，还是需要站内消息；是否接邮件或企业通讯工具。确认记录：________。

## 6 数据来源与接入

### D01 来源登记与负责人

- 建议阶段：一期。使用者：情报维护人员。
- 输入与操作：登记名称、网站或公众号或论文类型、地址、技术方向、负责人、可用范围和启停状态。
- 输出与规则：形成来源台账；停用保留历史来源标识和已有数据，不继续自动调度。
- 异常与权限：无效地址、重复编码有提示；来源编辑与仅查看分权，不允许任意内部地址请求。
- 验收：能按来源追溯内容及运行；来源改名后旧报告引用不被静默改写。
- 待确认：首批来源清单、维护人、来源授权依据和停用策略。确认记录：________。

### D02 爬虫数据接入规范

- 建议阶段：一期必需。使用者：爬虫开发方与平台维护人员。
- 输入与操作：通过确认的接口或批量文件提交来源ID、外部ID、标题、正文、原文链接、发布时间和采集时间。
- 输出与规则：返回接收批次、逐条结果和错误；同一来源外部ID重复提交有幂等规则。
- 异常与权限：凭证、格式、大小、频率和必填校验；单条失败不吞掉整批或误报全部成功。
- 验收：用同批次重复提交、缺字段、非法时间、断线重发等样本验证，并能追到后续处理结果。
- 待确认：接口或文件方式、字段映射、批量规模、爬虫交付方、完成回执方式。确认记录：________。

### D03 适配器与采集规则

- 建议阶段：首批来源一期，通用可视化规则可二期。使用者：维护人员。

## 11 三类科研材料的具体内容

本章是模板内容讨论基线。历史规格转述了样表字段，但正式交付必须以业务方确认的最新样表为准。项目名称、单位、联系人、预算、研究指标等真实值由业务人员提供，AI不得自动填写成事实。

### 11.1 科研需求报告

建议章节包括需求名称与摘要、生产背景与问题、国内外技术现状、已有研究基础、研究目标、研究内容、关键技术与创新、考核指标、预期成果、应用场景、实施计划和风险。应确认是独立科研需求文稿，还是正式项目填报表的另一种叫法；若是同一成果，避免重复建设两个入口。

| 讨论对象 | 需要确认的内容 | 验收材料 |
| --- | --- | --- |
| 业务问题 | 设备或工艺对象、现状、痛点、影响、现有解决方式 | 真实需求描述和支撑材料 |
| 研究目标 | 总目标、年度目标、可量化要求与约束 | 已确认指标，不能由AI编造 |
| 研究内容 | 任务分解、相互关系、关键技术与验证方式 | 一份认可的成果示例 |
| 预期成果 | 报告、软件、装备、标准、知识产权等形式 | 成果类别与数量规则 |
| 风险和应用 | 应用场景、试点条件、技术与实施风险 | 业务审核口径 |

### 11.2 技术路线报告

建议结构为目标与约束、关键技术问题、任务分解、技术方法、输入输出、依赖关系、试验或仿真方案、验证指标、阶段计划、里程碑、成果和风险。路线图应来自这些内容，不使用与当前报告无关的固定案例。

必须确认“技术路线”是概述性方法说明，还是能够执行的试验方案。后者需要试验条件、样本、设备、对照方法和评价指标，不能只增加几段生成文字代替专业设计。

### 11.3 科技项目需求填报表

建议封面字段逐项确认：需求名称、需求级别、需求类别、需求类型、技术业务域、技术图谱子技术、研究起止时间、填报单位、联系人、联系方式、填报年月。枚举值、必填条件和单位层级需由业务方给定。

历史规格记录六部分正文：生产需求及技术问题；国内外技术现状分析；研究目标；研究内容；预期研究成果；经费需求。其中国内外现状包括集团研究基础、国内现状、国外现状和分析结论；目标区分总体与年度；成果区分关键技术、技术经济指标和知识产权指标。是否仍采用该结构，以最新样表确认。

经费表需要单独开发和验收。至少确认预算年度、金额单位、资本化与费用化规则、明细科目、各年度小计、总计及勾稽关系。历史规格中的设备、软件、材料、试验、外部加工、委托研发、技术服务、差旅、会议、人员等科目只能作为讨论清单，不能未经确认全部硬编码为正式财务制度。

- 由人员填写金额，系统计算小计和合计；是否需要公式保留在Word中另行确认。
- 年份变化时列数和小计同步变化，空值和零值区分，避免重复汇总父子科目。
- AI可以按明确要求说明预算依据，但不能编造真实报价、税率和已批准金额。
- 导出后表格跨页、单位、精度、合计和签字位置应与样表逐项比对。

### 11.4 各模板必须提交的材料

每种类型至少提供一份空白正式模板、一份允许使用的完成样例、字段解释、必填与可改章节、字体与版式要求、数据来源和审核人。涉及经费表、图形或附件，需分别提供样例。缺样表时可先做通用草稿，不承诺正式报送版式已经完成。

## 15 成果审核发布与管理

### A01 作者定稿与正式成果边界

- 建议阶段：一期基础。使用者：作者。
- 输入与操作：完成内容及引用核对，解决阻断问题，确认定稿；按规则转审核或正式导出。
- 输出与规则：记录作者、时间和修订；定稿是作者复核，不自动等于领导批准或集团立项。
- 异常与权限：实质修改撤销旧定稿状态；未完成检查不能伪装正式稿。
- 验收：草稿、定稿和发布显示不同，修改后重新复核，导出门槛符合确认政策。
- 待确认：作者是否可直接正式导出，哪些材料必须审核后才允许外发。确认记录：________。

### A02 提交审核与任务分配

- 建议阶段：简单单级审核建议一期或一期增强，需业务确认。使用者：作者与审核负责人。
- 输入与操作：选审核人或按规则分配，提交指定版本，审核人查看正文与所需证据。
- 输出与规则：审核对象是固定修订，提交后是否锁定明确；被分配人员只获得必要访问权。
- 异常与权限：审核人离岗、无权限或自审冲突有处理规则，不以技术管理员默认代替业务审核。
- 验收：只有指定角色可审，提交后内容变化使审核失效或要求重新提交。
- 待确认：一期是否需要审核、单人或多人、能否自审、替审和分配人。确认记录：________。

### A03 审核意见退回与重提

- 建议阶段：随审核功能。使用者：审核人员与作者。
- 输入与操作：记录整体或章节意见，通过、退回、转交，作者修改后重新提交。
- 输出与规则：意见、答复、操作人、时间和被审版本可追溯；“通过”不删除先前退回记录。
- 异常与权限：超时提醒按需启用，审核中作者修改不能悄悄替换审核依据。
- 验收：完整走一轮退回重提通过，历史意见与对应内容版本能核对。
- 待确认：只需整体意见还是段落批注、转交规则、审核时限。确认记录：________。

### A04 发布撤回与阅读范围

- 建议阶段：一期明确规则，可按实际业务启用。使用者：获授权发布人。
- 输入与操作：发布审核通过或按规则定稿的成果，设置范围，必要时撤回并记录原因。
- 输出与规则：发布锁定内容，撤回不清除审计；内部公开与互联网公开不同，默认不对外匿名开放。
- 异常与权限：技术管理员需另有业务授权；已下载文件不能保证自动远程收回，应说明处置责任。
- 验收：普通用户不能伪造发布请求，撤回后新访问和引用受控，历史发布记录完整。
- 待确认：谁可发布、哪些成果公开、撤回后导出权限及对已外发文件的通知机制。确认记录：________。

### A05 成果库归档与统计

- 建议阶段：一期基础查询，复杂统计二期。使用者：授权业务人员与负责人。
- 输入与操作：按类型、方向、作者、单位、时间、周期和状态检索，查看版本及授权输出。
- 输出与规则：统计分别定义任务数、成果数、定稿数和发布数；重试、重复导出不重复算成果。
- 异常与权限：私有成果不向无权人员泄漏标题，删除或归档不破坏必要审计。
- 验收：负责人统计与具体成果对账，简报按覆盖周期检索，科研按真实业务字段检索。

### A06 成果共享与下载授权

- 建议阶段：一期私有与发布范围，部门项目共享可二期。使用者：作者和获授权阅读者。
- 输入与操作：明确授予查看、编辑或下载，选择人员或组织，设期限并撤销。
- 输出与规则：共享报告与共享原始资料分开，编辑权不自动获得发布权，导出快照也受控制。
- 异常与权限：权限回收后现有页面和下载重新检查；跨账号本机缓存不能遗留正文。
- 验收：A共享给B但不共享给C，各接口和文件一致；撤销后新访问失效。

## 18 全局体验与质量指标

### 18.1 页面与交互要求

登录后的业务页面统一标题、间距、筛选、按钮、表格和分页规则，按内容区域宽度适配。建议覆盖手机约375像素、平板约768像素、小桌面约1024像素和大桌面约1440像素；这些是测试尺寸建议，不代表已有验收结果。大表格允许内部横向滚动，但关键按钮不能被裁掉。

加载中、空数据、无权限、系统失败和模型不可用应分别呈现。上传、删除、重试、恢复版本、审核、发布和导出必须有真实状态；危险操作说明影响并确认。长时间任务后台执行，界面可离开再回来。键盘操作、清晰焦点、足够对比度和不只依赖颜色的状态提示作为统一要求。

图形编辑和长文编辑可以使用专用布局，但需要解释滚动区域和保存状态。登录封面不纳入本轮视觉改版。

### 18.2 建议指标与确认口径

下表中的数值只是讨论起点，必须结合数据量、并发、设备、网络和模型限流后确认。不得直接作为已经达到的性能事实或合同承诺。

| 指标 | 建议讨论值或定义 | 必须同时确认的条件 |
| --- | --- | --- |
| 列表与关键词检索 | 建议95%的请求在3秒内返回 | 正式数据量、并发数、冷热缓存、测试网络 |
| 保存反馈 | 建议95%的保存请求在2秒内反馈 | 长文大小、附件不计入、并发编辑情形 |
| 任务接收 | 建议3秒内取得任务ID，正文生成另计 | 队列可用、最大积压与拒绝策略 |
| 解析与生成时间 | 按文件页数、字符数、章节数分档实测后定 | 模型型号、限流、超时、降级是否算完成 |
| 数据字段完整率 | 必填字段完整记录数除以应入库记录数 | 必填定义、原始缺失与系统丢失分别统计 |
| 过滤效果 | 相关样本漏收率与不相关样本误收率分别计算 | 业务标注集、边界样本、抽样与允许上限 |
| 去重效果 | 重复残留与误合并分别统计 | 精确重复和相似事件两种口径 |
| 引用可追溯 | 已检查关键事实中可定位来源的比例 | 哪些事实必需引用、抽查规模、授权证据 |
| 模板完整 | 必填字段和章节全部具备，版式逐页比对 | 各类型最新样表、长文和空值样本 |
| 权限安全 | 必测越权场景全部拒绝 | 详情、片段、版本、图形、下载与后台调用 |
| 备份恢复 | 数据丢失窗口和恢复时间由运维方确认 | 备份频率、文件体量、隔离恢复环境 |

## 20 真实业务验收场景

本章先用于讨论“用什么证明功能做对了”，开发完成后再执行。每个场景至少记录账号、样本ID、配置版本、操作、实际结果、截图或文件；目前均未预填为通过。

### S01 一批情报从接入到正式阅读

选一个确认来源，提交同时含有效、缺字段、重复、不相关和模型失败的数据批次。检查逐条接收、计数、原始快照、规则版本、处理结果、人工修正和审核。普通用户只能看到满足条件的最终内容，标题、摘要、分类和评分与审核结果一致。关联D02、D06、F01至F12、I01、I02。验收负责人____；结果____。

### S02 过滤提示词变更与回退

使用固定标注样本测试旧新版，比较误收和漏收；测试不改正式数据。发布后新运行使用新版，旧运行可追溯原版本。选小批量重处理并保护人工修正，再回滚验证。关联F05、F09、F12、C05、C06。验收负责人____；结果____。

### S03 文件上传安全解析与权限

A上传私有DOCX、可搜索PDF及不支持样本，混入超限、损坏和风险文件。扫描失败或待扫描不能进入解析与AI；成功正文与原文件相符。B不能通过搜索、ID、片段、下载或导出访问私有资料。关联K01至K08、O02、O03。验收负责人____；结果____。

### S04 搜索跨页选材与资料失效

从资讯、论文和内部资料的搜索结果及第二页加入资料篮，刷新并创建任务，核对类型和快照。随后撤回一条来源或收回授权，生成时发现不可用，不误用缓存。关联P03至P05、I07、R03。验收负责人____；结果____。

### 22.4 范围冻结与后续变更
