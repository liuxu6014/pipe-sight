# 国家管网科技情报与科研辅助平台功能说明与逐项核对清单

编制日期：2026-10-12。适用范围：当前 PipeSight 项目工作区，包含已融合的 InsightHub PostgreSQL 数据处理能力。

这份说明用于逐项核对当前产品，而不是未来功能规划。普通用户使用业务门户，管理员维护数据、模型、模板和权限；两者共同支撑“获得资料—形成证据—生成草稿—人工复核—成果发布或导出”的业务链路。

阅读建议：先看第 2—3 章了解产品组成和主流程；普通用户逐项核对第 4—13 章，管理员逐项核对第 14—18 章。第 19 章列出统一验收要求，第 20 章集中列出不能认定完整交付的事项，第 21 章提供真实使用链路，第 23 章可直接作为问题记录表。

## 1 核对口径与使用方法

### 1.1 先区分功能存在与验收通过

本文依据当前前端页面、已注册 API、后端服务、任务入口和部署配置整理。代码基线为 `222c943` 及其当前工作区改动；工作区有大量尚未提交的改动，因此不能只根据该提交号复现全部现状。

### 1.2 建议准备的核对样本

- 管理员一个、普通用户 A 和 B 各一个；不要使用同一管理员账号代替权限隔离测试。
- 已审核资讯、待审核资讯、被拒绝资讯各一条；有原文链接和无原文链接的样本各一条。
- 只有元数据的论文、开放获取论文、访问受限论文各一条。
- 私有 TXT、DOCX、可搜索 PDF；扫描 PDF、旧 DOC、损坏文件、大文件和疑似可执行文件各一个。
- 三类已发布科研模板、日报／周报／月报模板；另准备草稿模板和停用模板。
- 配置可用的 `research`、`digest`、`data-filter` 模型路由，并准备不可用路由验证失败反馈。
- 验收用来源、采集运行、普通科研任务、失败任务、未定稿报告、已定稿报告及已发布报告。

## 3 全项目业务主线

### 3.1 外部情报链路

来源配置 → 采集运行 → 本地规则清洗与目录入库 → 可选 InsightHub 交接 → 外部处理状态及结果快照回写 → 内容审核 → 用户端检索与阅读。

本地规则结果和外部处理结果是两层数据。当前回执同步主要保存状态、外部 ID 和结果 JSON，不会自动以外部标题、摘要、评分和分类覆盖目录字段。这是核对“处理效果是否真的进入用户列表”时必须确认的边界。

采集成功、处理成功和审核通过是不同结果。某条数据被过滤拒绝，不应自动算作采集故障；未经审核通过的数据不应以正式公共资讯展示。

### 3.2 内部资料链路

文件上传 → 安全扫描 → 后台解析 → 可用性确认 → 受控查看／下载 → 加入资料篮 → 作为本人科研任务证据。

上传成功仅代表接收了文件。只有扫描通过、解析成功、具有内容且允许 AI 使用的资料，才进入科研证据集合。

### 3.3 科研成果链路

选择已发布模板 → 填写方向和要求 → 选择授权资料 → 配置章节 → 创建持久任务 → 组织证据与生成章节 → 编辑草稿 → 质量检查与人工复核 → 定稿 → 正式导出，或由管理员正式发布。

### 3.4 情报简报链路

选择日报／周报／月报与周期 → 设置来源和方向 → 选择当期候选资讯 → 生成简报 → 编辑与核对来源 → 定稿／导出。可另建周期自动计划，由 Worker 到期派发任务；自动派发不等于自动发布。

### 15.1 数据处理链路

InsightHub 已并入 `backend/src/app/intelligence/processing/`，默认目标是同一 PostgreSQL 数据库的 `news` schema，而不是另开一套独立项目。处理进程与 API、通用任务 Worker 的职责不同。

本地与外部规则的实际差别：

- 本地清除 HTML、脚本、样式和隐藏字符，规范 URL／DOI，生成 SHA256、SimHash，记录质量问题。缺标题／有效地址等强制失败；是否保留还依赖固定相关性阈值 70。
- 本地六组主要标签为管道完整性、腐蚀防护、监测预警、数字化智能化、工程建设、安全环保；未命中标记待人工确认。相关性分数和质量分不是同一指标，也不是模型置信度。
- 本地未保留记录主要进入过滤摘要和计数，不代表每条都进入人工审核库。
- 外部 Worker 有自己的标题、正文、来源和时间过滤；非机构来源超过 30 天可能被过滤。相关规则不是来源页面可配置的时间窗口。
- proofwords 依赖领域及实际词表，仓库未内置相应业务文件；默认严格领域配置不能等同于 tech 领域严格过滤已经启用。
- Worker 分类、摘要、评分、小模型和领域配置还有环境、文件与数据库读取路径，不能认定全部受后台单一 Prompt／模型路由控制。

运行支撑的具体限制：

- 系统定时任务白名单为 app.，黑名单又包含 app，新增／普通编辑先检查黑名单，因此符合白名单的目标也会被拒绝。这与持久科研、采集 Worker 是不同入口，不能由此认定所有业务调度都不能工作。
- 在线用户是 Redis 认证会话，不是实时在场人数；该列表的查询也不是完整服务端分页浏览。
- 操作日志主要覆盖显式添加日志装饰器的操作，不保证所有浏览行为均入库；服务监控是 API 所在环境与进程，不是集群监控。
- 缓存“清理全部”可能删除当前 Redis 数据库全部键并重建字典／配置，影响会话等状态；当前查询与清理共用权限，需单独审视授权。
- 通用上传上限当前为 50 MiB，与资料库 16 MiB 不同。MP4 在扩展名白名单中但无匹配文件头规则，不能承诺可上传；通用上传不自动扫描或建立知识库资料。
- 头像仅公开挂载专用目录，非头像上传 URL 不等于匿名可下载。通用资源下载需要补充与资料受控下载一致的资源归属核验。
- 存活探针为 /health/live；就绪探针 /health/ready 检查 PG 与 Redis，不检查模型、来源、扫描器或 Worker 工作效果。文档 UI 关闭不必然关闭 OpenAPI schema。
- 本地 CLI／TUI 直接使用服务器配置，不能按网页 RBAC 理解；危险数据库、缓存等操作需遵守其确认和环境保护机制。

## 19 状态、权限与全局交互规则

### 19.1 核对时要分开的状态

| 对象 | 主要状态或结果 | 说明 |
| --- | --- | --- |
| 上传扫描 | pending、clean、quarantined、failed | 只有 clean 才通过安全门禁 |
| 文件解析 | queued、parsing、indexed、failed | indexed 是文本解析状态，不是向量索引完成证明 |
| 科研任务 | queued、running、completed、failed、cancelled、dead_letter | completed 表示执行产生结果，报告仍可能是草稿 |
| 模型执行 | model、model-partial-fallback、deterministic、deterministic-fallback | 区分全部模型章节、部分降级、未配路由及调用失败 |
| 报告成果 | draft、completed、published 等实际流程状态 | 人工定稿、管理员发布和任务完成不可混用 |
| 自动简报计划 | queued、no_data、skipped、failed 等最近结果 | 计划状态不是所派发报告的最终审核状态 |
| 导出任务 | queued、running、completed、failed 等实际处理状态 | 导出完成后才有可下载文件 |

| 通用文件下载权限 | 目录边界检查不能替代文件所有权及业务权限 | 补齐或验证保护后再验收 |
| 外部处理映射进目录 | 回执目前只保存结果快照，不自动替换标题／摘要／评分／标签 | 以实际目录字段逐项比对 |
| 可视化分类标签规则 | 来源类别与标签展示不等于规则编辑器 | 当前没有完整管理 UI |
| 高级引用格式 | 已有复制引用不等于完整 GB/T、APA、BibTeX 管理器 | 单独确认需求与实现 |
| 多级审批与协同编辑 | 版本／定稿／发布审计不等于多人实时编辑、专家分派和会签审批 | 不计为完整流程 |
| 部门／项目级共享 | 当前资料主要是 private／public，不能代替逐人或组织授权 | 单独补充权限模型与页面 |
| 图形页面完整闭环 | 常规入口缺失、默认案例残留、类型切换有限、备份未按账号隔离 | 不按已完成的报告配图闭环验收 |
| 简报页面与科研编辑器对齐 | 标题编辑、历史恢复、导出记录等入口不齐，追加候选未严格约束原周期 | 逐项记录差异 |
| 翻页／搜索资料选择 | Store 之外条目可能被误识别类型或缺快照 | 以跨页样本核对 |
| SSO 与 MFA | 当前账号密码与 RBAC 体系不等于集团统一身份、多因素认证 | 单独对接 |
| 订阅与外发通知 | 自动计划不等于邮件／短信分发、关键词预警和站内通知中心 | 不默认承诺 |
| 部门、岗位、通知公告、代码生成器 | 当前精简底座中已移除相关业务模块 | 不按若依原版菜单验收 |
| 专业安全扫描 | basic 模式只做基础检查，不代替病毒库扫描及安全合规验收 | 生产必须明确扫描策略 |
| 生产运维就绪 | 容器配置、测试代码和健康接口不代替备份恢复、告警、容量及安全演练 | 独立上线验收 |

## 21 全流程核对场景

以下为验收步骤，不是本次已经执行通过的结果。

### 场景 A 普通用户阅读与证据准备

- [ ] A1 用户 A 登录，导航仅出现业务功能。
- [ ] A2 在资讯列表组合筛选，打开一条资讯，核对来源、时间、摘要和正文。
- [ ] A3 收藏该资讯并加入资料篮；刷新后在“我的收藏”和资料篮找到同一条记录。
- [ ] A4 检索论文并查看摘要、DOI、全文状态；受限论文不出现假全文下载。
- [ ] A5 打开来源，核对实际地址；缺链接样本明确不可跳转。
- [ ] A6 请求待审或拒绝内容，验证普通用户不能当作正式公共证据使用。

### 场景 B 文件上传、隔离与解析

- [ ] B1 用户 A 上传私有 TXT 或 DOCX，记录资料 ID 和上传后状态。
- [ ] B2 等待扫描与后台解析，状态从排队转为成功，正文可查看。
- [ ] B3 用用户 B 直接访问相同 ID 的详情、下载和重试 API，验证无权。
- [ ] B4 上传公开资料，用户 B 可按公开规则查看，但不能冒充所有者删除。
- [ ] B5 上传扫描 PDF、旧 DOC、损坏文件和超限文件，验证提示与实际限制一致。
- [ ] B6 在验收环境关闭扫描器或提供风险样本，验证待扫描／隔离资料不能进入 AI 和下载链路。
- [ ] B7 对失败资料重试，核对新状态和错误；删除本人资料后核对列表与文件结果。

### 场景 C 三类科研报告

- [ ] C1 分别选择三类已发布模板，核对章节、字数和必填项不同且正确。
- [ ] C2 填写方向、场景、关键词和生成要求，至少选一条就绪资料。
- [ ] C3 调整大纲、提交两次相同请求标识，确认只形成一个任务。
- [ ] C4 关闭创建页再打开任务，观察真实阶段、日志、所用模板及证据。
- [ ] C5 检查研究模型审计，确认实际使用的 DeepSeek 或其他模型，而不是仅看到模型配置。
- [ ] C6 对无路由和路由失败分别测试，确认降级草稿有警告，不伪装正式完成。
- [ ] C7 查看章节引用，逐条与真实资料比对事实和数字，证据不足处不得靠模板文字冒充依据。
- [ ] C8 对三类报告分别核对客户期望结构；项目填报表额外比对封面字段和经费表，记录未覆盖项。

### 场景 D 编辑、冲突、版本、定稿与发布

- [ ] D1 修改标题、章节正文及结构，观察自动保存，刷新验证结果。
- [ ] D2 两个页面同时编辑同一报告，后保存者收到修订冲突，不静默覆盖。
- [ ] D3 创建版本、预览旧版、恢复旧版，确认新版本保留且重新待复核。
- [ ] D4 制造空章节、无引用或失效引用，验证高等级问题阻止定稿。
- [ ] D5 消除阻断、人工核对事实后定稿；再编辑正文，确认回到待复核。
- [ ] D6 普通用户尝试正式发布被拒绝；管理员发布已定稿成果并查看审计。
- [ ] D7 发布后尝试正文、图形、恢复版本操作被拒绝；撤销发布后再编辑。

### 场景 E 图形与三种文件导出

- [ ] E1 按已知报告 ID 打开图形路由，记录常规入口缺失问题；调整结构、保存并重新打开。
- [ ] E2 下载实际支持的图形格式，独立打开验证；另检查图形是否真的进入 Word／PDF，不能想当然。
- [ ] E3 对未定稿报告执行正式导出被拒绝，显式草稿导出文件名含草稿标识。
- [ ] E4 对同一已保存修订分别导出 Markdown、DOCX、PDF，内容和引用一致。
- [ ] E5 验证中文、长标题、长段落、分页及缺少来源字段时的导出版式。
- [ ] E6 查看异步导出记录、状态、版本和文件大小，重新下载文件验证一致性。
- [ ] E7 用户 B 访问用户 A 的私有导出 ID 被拒绝。

### 场景 F 日报周月报及自动计划

- [ ] F1 分别选择日、周、月周期，边界样本覆盖跨月、跨年和无候选日期。
- [ ] F2 核对候选来源、方向、去重、条数及摘要长度，确认实际作用，不仅检查选项保存。
- [ ] F3 创建简报，检查 digest 模型审计、来源清单、编辑、定稿与导出。
- [ ] F4 创建自动计划，核对上海时区、执行时间、前期范围和下次时间。
- [ ] F5 暂停、启用、补跑及删除计划，核对后端状态与列表一致。
- [ ] F6 无候选期显示 no_data；配置节假日命中时按策略跳过；两者都不伪造正文。
- [ ] F7 重启 Worker 或模拟重复派发，验证不生成重复任务；自动计划不自动正式发布。

### 场景 G 来源采集、处理与治理

- [ ] G1 建立一个明确获授权、已配置适配器的真实来源；另准备不可用来源。
- [ ] G2 配齐已发布 data-filter Prompt、模型和路由，执行试采，记录运行 ID。
- [ ] G3 查看规范化采集记录、运行摘要、交接记录、处理 Worker 输出及回执计数，核对同一批次可追溯；不把规范化记录当作原始响应存档。
- [ ] G4 用相关、不相关、重复和缺字段样本核对过滤、分类、标签、评分及拒绝原因。
- [ ] G5 修改并发布 Prompt 后重跑，确认新运行使用新版，旧运行快照不变。
- [ ] G6 审核通过／拒绝后，核对普通用户列表及生成证据可见性变化。
- [ ] G7 执行单条／批量治理和重复组操作，核对审计、逐条失败及最终结果。
- [ ] G8 停用来源、停止处理 Worker、模拟失败后恢复，确认状态诚实且可追溯。

### 场景 H 权限、会话和运行保障

- [ ] H1 给管理角色只授列表权限，确认不能越权保存、审核、发布、导出或运行任务。
- [ ] H2 A 退出、B 登录，检查资料篮、收藏、任务轮询、编辑状态全部隔离。
- [ ] H3 检查前端、API、PG、Redis、通用任务 Worker 和 InsightHub Worker，而不仅检查前端首页。
- [ ] H4 验证数据库、模型、文件存储、扫描器异常分别有明确反馈。
- [ ] H5 在手机、平板、小桌面和大桌面下检查业务页面；管理侧栏展开／收起后不挤出操作区。
- [ ] H6 上线前另行完成备份恢复、日志保留、凭证轮换、访问策略、容量及告警验收。
- [ ] H7 单独核对通用 AI 会话详情、删除、取消和模型使用权限，不能用“列表只返回本人”替代资源归属验证。
- [ ] H8 核对通用资源下载与资料库下载权限一致性；系统定时任务新增／编辑校验冲突需修复后复测。

## 23 核对结果记录模板

每个问题独立记录，编号引用本文功能项或场景步骤，避免只写“这里不合理”。

| 字段 | 填写内容 |
| --- | --- |
| 功能编号 | 例如 LIB-14、RES-13、D2 |
| 结果 | 通过／不通过／不适用／待配置 |
| 环境和账号 | 部署地址、版本、用户角色，不记录密码或 API Key |
| 前置数据 | 来源／资料／模板／任务／报告 ID |
| 操作步骤 | 按实际点击和输入顺序记录 |
| 预期结果 | 引用本文并补充业务要求 |
| 实际结果 | 描述界面、数据及文件结果 |
| 证据 | 截图、脱敏日志、导出文件和接口信息 |
| 后续处理 | 修复／补配置／需求确认／不在范围 |

完整验收应同时满足页面可用、权限正确、数据持久化、失败反馈诚实、文件产物可用及关键链路可恢复。不能把“项目有这些代码”直接换成“所有功能已经合格”。
