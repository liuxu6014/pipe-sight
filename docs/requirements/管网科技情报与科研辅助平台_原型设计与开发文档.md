# 管网科技情报与科研辅助平台：原型设计与开发文档

> 本文档承接《管网科技情报与科研辅助平台_功能清单与需求规格.md》，用于直接生成高保真原型、拆分前后端任务、设计数据库与 API、制定测试和上线计划。
>
> 技术基线：Vue 3 + Vite + Element Plus + Pinia + Vue Router；FastAPI 若依 Python 版；MySQL、Redis、对象存储、全文检索和向量检索。

## 1. 研发总体原则

1. 保留若依的登录、用户、角色、菜单、按钮权限、数据权限和日志能力。
2. 用户门户和后台控制台使用两个清晰的界面壳层，共享同一套账号和权限服务。
3. 普通用户端使用业务化顶部导航，不显示若依后台侧边栏。
4. 资讯、论文、资料、报告和日报周报全部使用真实 API 和持久化数据，不在正式版本保留内存模拟数据。
5. 采集、解析、向量化、生成、翻译和导出都是异步任务，前端通过轮询或 SSE 获取状态。
6. AI 输出必须模板化、可编辑、可引用、可版本化、可审计。
7. 原型先覆盖完整业务闭环，再逐步替换模型、采集器和存储实现。

## 2. 原型视觉规范

### 2.1 总体体验

- 产品气质：权威、克制、平静、可信、适合长时间阅读。
- 普通用户端：资讯产品布局，强调搜索、阅读和科研任务，不使用后台表格堆叠式首页。
- 管理员端：沿用若依成熟管理布局，强调效率、状态、筛选和批量操作。
- 登录页：参考 Calm 首页的沉浸式全屏氛围，但使用国家管网品牌标识和平台文案；点击入口后出现居中浮窗登录。
- 用户端布局可继续复用既有 `intellinews-demo` 的信息门户结构，导航和内容层级必须按本项目重新命名。

### 2.2 品牌元素

- 官方图标来源：`https://www.pipechina.com.cn/Uploads/Picture/2023/09/05/s64f6d50827d73.png`，生产环境使用已下载并审核的本地资源。
- 平台名称：国家管网科技情报与科研辅助平台。
- 主色：深海蓝 `#0B2A3D`。
- 辅色：科技青 `#1E7E8C`、雾蓝 `#EAF2F5`。
- 品牌强调色：仅在 Logo、关键状态或重要按钮中少量使用红色/暖色，不大面积铺红。
- 正文：`#1F2933`；次级文字：`#667784`；分割线：`#D9E3E8`。
- 成功：`#2E7D5B`；警告：`#C98723`；错误：`#B54343`。

### 2.3 字体与密度

- 中文首选：系统 UI 字体、思源黑体或苹方/微软雅黑回退。
- 标题 32/28/24/20 px，正文 16 px，辅助文字 13-14 px。
- 阅读页正文行高 1.75，最大正文宽度 820-900 px。
- 后台表格正文 14 px；用户端卡片正文不低于 15 px。

### 2.4 响应式断点

- 设计基准：1440×900。
- 桌面：≥1280 px，完整导航和双栏详情。
- 平板：768-1279 px，筛选面板改抽屉，右侧目录可折叠。
- 手机：≤767 px，顶部导航改菜单，列表单列，报告编辑提供只读/简化编辑模式。
- 高保真原型至少输出 1440 桌面和 375 手机两个版本的登录、首页、资讯列表、详情和任务页面。

### 2.5 全局组件

- `PortalHeader`：Logo、一级导航、全局搜索、任务状态、头像菜单。
- `GlobalSearchBox`：支持搜索建议、历史、类型快速切换。
- `FilterBar/FilterDrawer`：多条件筛选、已选条件标签和一键清空。
- `ContentCard`：资讯/论文的统一卡片骨架。
- `SourceBadge`：新闻网站、公众号、论文、内部资料等来源标识。
- `TagGroup`：技术标签、业务分类、重要程度。
- `TaskProgress`：阶段、进度、耗时、日志和失败重试。
- `CitationDrawer`：展示引用来源、文件、页码/章节和原文片段。
- `VersionTimeline`：报告或图形的版本列表、修改人和操作。
- `EmptyState/ErrorState/Skeleton`：统一空、错、加载状态。

## 4. 用户端页面原型规格

### UI-01 登录页

**目标**：建立平台品牌感，并以浮窗完成登录鉴权。

**页面结构**：

1. 全屏背景：宁静的山水/管网基础设施抽象景观，带深色渐变遮罩。
2. 左上品牌区：国家管网图标 + 平台全称。
3. 顶部右侧：登录按钮，可选“平台介绍/帮助”，不要出现后台入口。
4. 中央主文案：一句短标题和一句副标题；不展示演示账号、账号说明、角色说明、USER SIGN IN 等冗余文本。
5. 底部轻量入口：科技资讯、论文资料、科研生成、日报周报四个价值说明卡片；点击未登录业务入口时打开登录浮窗并保存目标地址。
6. 登录浮窗：账号、密码、验证码、记住我、登录按钮；右上关闭按钮。

**交互**：

- 页面初次加载时浮窗默认关闭。
- 点击“登录/开始使用/任一业务入口”打开浮窗。
- Esc 关闭；提交期间禁止重复提交；登录失败保留账号、清空密码/验证码并刷新验证码。
- 登录成功后根据目标地址进入用户端；管理员主动访问后台地址时才进入后台。
- 模态框打开后锁定背景滚动并将焦点置于账号输入框。

**状态**：默认、浮窗打开、输入错误、验证码加载失败、登录中、账号锁定、网络错误。

### UI-02 用户首页

**目标**：用一个页面完成“发现信息、继续任务、快速创建”。

**页面结构**：

1. 顶部欢迎区：日期、用户姓名、统一搜索框。
2. 快捷动作：新建科研报告、新建日报周报、上传资料、知识问答。
3. 今日概览：新增资讯、论文更新、待处理任务、最近报告。
4. 热点主题：5-8 个主题，展示热度、趋势和关联数量。
5. 最新科技资讯：6 条，标题、来源、时间、标签和摘要。
6. 最新论文：4-6 条，标题、作者、期刊、年份和关键词。
7. 我的工作：最近 5 个生成/导出/解析任务，展示进度和下一步操作。

**交互**：

- 搜索提交进入 `/portal/search?q=`。
- 点击卡片进入详情；快捷动作进入对应创建页。
- 任务进行中时 Header 显示状态点，点击打开任务面板。

**空状态**：没有任务时显示“创建第一份科研报告”；没有数据时提示管理员尚未配置数据源。

### UI-03 全局搜索结果

**目标**：跨数据类型检索，避免用户分别进入多个模块重复搜索。

**页面结构**：

- 顶部大搜索框，显示查询词、耗时和总结果数。
- 类型页签：全部、资讯、论文、内部资料、我的报告。
- 左侧/抽屉筛选：时间、来源、分类、标签、作者、期刊、资料权限。
- 主结果区：根据类型使用差异化卡片；关键词高亮。
- 右侧可选“相关主题/建议关键词”。

**交互**：

- 筛选条件同步到 URL，支持浏览器返回。
- 结果可加入资料篮、收藏或打开详情。
- 无权访问的资料不出现在搜索结果中。

### UI-04 科技资讯列表

**目标**：快速浏览、筛选新闻和微信公众号文章。

**页面结构**：

- 页面标题、说明、列表/卡片视图切换。
- 页签：全部、新闻网站、微信公众号。
- 筛选：时间、来源、业务分类、技术方向、标签、重要程度。
- 列表项：标题、来源、来源类型、发布时间、AI 摘要、标签、重要等级、缩略图（可选）。
- 右侧栏：热门主题、重点来源、最近更新。

**交互**：

- 点击标题打开详情；来源名可作为筛选条件。
- “加入资料篮”在卡片上提供快速操作。
- 重要程度说明可通过 Tooltip 查看评分规则。

### UI-05 资讯详情

**目标**：阅读、追溯原文，并进入科研分析流程。

**页面结构**：

- 面包屑、标题、来源、时间、来源类型、原文链接。
- AI 摘要和“业务影响/技术要点”摘要卡。
- 正文阅读区，保留段落和合法图片。
- 标签、分类、重要程度和处理时间。
- 操作：收藏、加入资料篮、生成摘要、引用到报告。
- 右侧：文章目录（长文）、相关资讯、相关论文。

**状态**：正文抽取失败时保留元数据、摘要和原文链接；原文失效时展示最后抓取时间。

### UI-06 论文列表

**目标**：按科研习惯检索和筛选论文元数据。

**页面结构**：

- 搜索框支持题名、作者、机构、DOI。
- 筛选：年份范围、期刊/会议、机构、关键词、开放获取状态。
- 论文项：标题、作者、机构、期刊、年份、摘要前两行、关键词、DOI、全文状态。
- 操作：查看详情、加入资料篮、引用导出、收藏。

**交互**：

- DOI 支持精确搜索。
- 全文不可用时按钮显示“查看来源”，不能显示误导性的“下载全文”。

### UI-07 论文详情

**页面结构**：

- 标题、作者及机构映射、期刊/会议、年份、DOI、来源链接。
- 摘要、关键词、引用信息、全文可用状态。
- 关联资讯、关联内部资料、相似论文。
- 操作：加入资料篮、生成研究要点、引用导出、上传有权使用的全文。

**版权状态**：开放获取、用户上传、仅元数据、访问受限四种状态必须清晰区分。

### UI-08 科研工作台

**目标**：统一承载资料选择、报告生成和最近工作，避免出现多个重复“工作台”。

**页面结构**：

- 主行动按钮：新建科研报告。
- 报告类型卡：科技项目需求填报表、科研需求报告、技术路线报告；P1 可增加论文/综述。
- 我的最近报告：标题、类型、状态、版本、更新时间。
- 生成任务：排队、生成中、待修改、已完成、失败。
- 资料篮：当前已选资料数量和类型，支持清空或进入创建任务。
- 模板推荐：默认模板和最近使用模板。

### UI-09 新建科研生成任务

**页面形态**：四步 Stepper，桌面端居中宽表单。

**步骤一：选择类型与模板**

- 报告类型。
- 模板版本。
- 输出语言。
- 预计篇幅。

**步骤二：选择资料**

- 从资讯、论文、内部资料、历史报告中选择。
- 支持搜索、批量勾选、已选资料篮。
- 显示权限、解析状态、来源和页数。
- 上传新资料后先进入解析任务，解析完成才可继续。

**步骤三：填写任务参数**

- 任务名称。
- 研究方向。
- 关键词。
- 业务场景。
- 项目名称/需求名称。
- 研究起止时间。
- 生成要求。
- 是否生成图形、图形类型。
- 是否允许使用公开资料补充。

**步骤四：确认大纲**

- 系统推荐章节。
- 拖拽排序、新增/删除、目标字数、章节说明。
- 资料覆盖提示：每章关联的候选资料数量。
- 提交后进入任务进度页。

**校验**：没有可用资料、无研究方向、模板失效、无权限资料必须阻止提交。

### UI-10 生成任务进度

**页面结构**：

- 任务标题、报告类型、创建人、创建时间。
- 总体进度条和当前阶段。
- 阶段时间线：资料校验、解析、检索、大纲、章节生成、引用、质量检查、图形、导出准备。
- 实时日志：只展示用户可理解的消息，技术堆栈仅后台可见。
- 输入资料摘要和所用模板/模型信息。
- 操作：取消、重试、复制任务、返回工作台。

**状态机**：draft、queued、parsing、retrieving、outlining、generating、validating、completed、failed、cancelled。

### UI-11 报告编辑器

**目标**：提供结构化编辑、引用和版本管理，不做简单大文本框。

**桌面布局**：

- 左栏：章节目录、完整性状态、拖拽排序。
- 中栏：当前章节富文本编辑器。
- 右栏页签：引用来源、生成建议、质量问题、版本记录。
- 顶部：保存状态、字数、报告类型、当前版本、预览、导出。

**核心交互**：

- 自动保存和手动保存。
- 选中文本后“改写、扩写、压缩、专业化、补充引用”。
- 对当前章节填写补充要求后生成候选内容；用户比较后确认替换。
- 点击引用角标打开来源抽屉并定位文件页码/章节。
- 质量检查项可点击定位到问题段落。
- 历史版本可预览、对比和恢复。

**科技项目需求填报表专属区**：

- 封面字段使用结构化表单维护。
- 经费需求使用可编辑表格；自动计算小计、年度合计和预算合计。
- 正文编辑与封面/经费数据分离保存，导出时合并。

### UI-12 图形编辑器

**页面结构**：

- 顶部：图形类型、布局方向、主题、撤销/重做、保存、导出。
- 左侧：节点库（阶段、任务、方法、验证、成果、普通概念）。
- 中央：画布，支持缩放、拖拽、框选、连线。
- 右侧：节点属性、样式、层级、关系、关联报告章节。
- 版本区：自动生成版本、人工修改版本、重新生成版本。

**交互**：

- 从报告章节一键生成。
- 选中分支后输入要求进行局部重新生成。
- 图形保存为结构化 JSON，PNG/SVG 只作为导出产物。

### UI-13 日报周报列表

**页面结构**：

- 新建报告按钮。
- 页签：全部、日报、周报、自动任务。
- 筛选：日期、技术方向、状态、创建人、模板。
- 列表：标题、类型、覆盖时间、来源数、状态、版本、更新时间。
- 操作：查看/编辑、复制、导出、查看来源、删除草稿。

### 6.2 状态管理

| Store | 主要状态 | 持久化策略 |
| --- | --- | --- |
| user | Token、用户、角色、权限、部门 | 沿用若依；Token 安全存储 |
| portal | 首页摘要、热点、导航状态 | 会话缓存 |
| materialBasket | 选中的资讯、论文、资料 | localStorage + 服务端草稿 |

| reportEditor | 当前报告、章节、保存状态、引用、质量问题 | 页面 Store；后端版本为准 |

### 6.3 路由守卫

1. `/login`、`/401`、`/404` 为公开路由。
2. 所有 `/portal/**` 必须有有效 Token。
3. 未登录访问业务地址时跳转 `/login?redirect=<fullPath>`。
4. 登录后加载用户信息和动态权限，再解析跳转地址。
5. 用户端身份访问后台路由返回 403，不回退到任意后台默认页。
6. 管理身份登录但目标是合法用户端路由时允许进入用户端。
7. 动态路由刷新后必须可恢复，避免首次正常、刷新 404。

### 6.4 API 请求规范

- 使用统一 request 封装，自动附加 Bearer Token、请求 ID 和语言信息。
- GET 查询参数统一使用后端约定的 `pageNum/pageSize`。
- 列表响应统一映射 `{ rows, total }`。
- 401 自动清理会话并跳转登录；403 展示无权限；业务错误展示后端 `msg`。
- 文件下载必须使用 Blob，并从响应头或业务数据取得文件名。
- 异步任务创建成功后返回 `jobId`，前端跳转任务页，不在提交按钮上长时间等待。

### 6.5 页面状态完整性

所有页面必须设计并实现：

- 初次加载骨架屏。
- 有数据状态。
- 空数据状态。
- 筛选无结果状态。
- 权限不足状态。
- 网络错误与重试。
- 局部操作失败回滚。
- 长任务进行中、失败、取消和完成。

## 7. 后端开发设计

### 7.1 模块边界

```text
backend/
├─ module_pipeline/            # 用户端情报与公共业务入口
├─ module_source/              # 数据源、采集规则、运行记录
├─ module_content/             # 资讯/论文标准化、标签、去重、数据质量
├─ module_knowledge/           # 文件、解析、切块、向量索引、知识问答
├─ module_research/            # 科研报告任务、报告、章节、版本、引用
├─ module_diagram/             # 图形节点、版本、导出
├─ module_digest/              # 日报周报任务、报告、来源清单
├─ module_translation/         # 翻译任务与术语库
├─ module_template/            # 报告/导出/Prompt 模板
├─ module_model_gateway/       # LLM、Embedding、重排、翻译、图形模型
├─ module_file/                # 对象存储、签名 URL、文件生命周期
└─ module_admin/               # 若依用户、角色、菜单、日志等既有模块
```

现有 `module_pipeline` 可保留为聚合 API；论文生成已迁入 `app.research`，旧 `module_manuscript` 仅保留兼容转发，避免形成与科研报告完全分离的第二套任务体系。

### 7.2 分层规范

- Controller：请求校验、鉴权、响应包装，不承载业务算法。
- Service：业务流程和事务边界。
- Repository/DAO：数据库读写和查询构造。
- Entity/VO：数据库模型、查询模型、响应模型。
- Worker Task：耗时任务，只通过明确的服务接口修改状态。
- Adapter：爬虫、模型、对象存储、搜索、向量库等外部系统适配。

### 7.3 基础设施建议

| 能力 | 建议实现 | 用途 |
| --- | --- | --- |
| 关系数据库 | MySQL 8.x | 用户、权限、元数据、任务、报告、版本、日志 |
| 缓存/队列 | Redis | 缓存、分布式锁、任务状态、Celery Broker |
| 异步任务 | Celery Worker | 采集、解析、向量化、生成、翻译、导出 |
| 定时触发 | 若依定时任务/APScheduler | 触发采集、日报周报和备份；实际耗时工作投递 Celery |
| 对象存储 | MinIO/S3 | 上传资料、原始文件、图片、图形和导出文件 |
| 全文检索 | OpenSearch/Elasticsearch | 中文全文检索、筛选、聚合和热点统计 |
| 向量检索 | Qdrant/Milvus | 文档片段语义检索 |
| 模型网关 | OpenAI-compatible API | 统一接入 Qwen 70B/235B 或其他模型 |
| 文档解析 | python-docx、PyMuPDF/pdfplumber、Markdown parser | 结构化抽取 |
| Word/PDF 导出 | python-docx/OOXML + LibreOffice | 套用模板并渲染验收 |
| 图形 | Mermaid/自定义节点 JSON + SVG 渲染 | 思维导图、概念图、技术路线图 |

### 7.4 模型网关

统一接口至少包含：

- `chat_completion`：普通/流式文本生成。
- `embedding`：文本向量化。
- `rerank`：检索结果重排。
- `translate`：术语约束翻译。
- `structured_generate`：按 JSON Schema 输出大纲、标签、节点和质量结果。
- `health_check`：模型可用性、延迟和配置验证。

每次调用记录：业务任务 ID、用途、模型配置 ID、Prompt 版本、耗时、Token、状态和脱敏错误。模型密钥只在服务端解密使用。

## 10. 异步任务与状态机

### 10.1 通用任务状态

```text
draft -> queued -> running -> completed
                 |-> failed -> queued (retry)
                 |-> cancelling -> cancelled
```

### 10.2 状态要求

- `progress_pct` 只能前进，重试时创建新的 attempt 或明确重置原因。
- `current_stage` 使用稳定枚举，前端通过映射显示中文。
- 用户取消只发起取消请求；Worker 在安全点确认后进入 `cancelled`。
- 每次重试记录 attempt、错误、开始结束时间和 Worker ID。
- 状态写入数据库，Redis 只用于加速和事件通知。

### 10.3 科研生成阶段

1. validating_inputs
2. parsing_materials
3. retrieving_evidence
4. building_outline
5. generating_sections
6. linking_citations
7. validating_quality
8. generating_diagrams
9. preparing_export
10. completed

### 10.4 任务进度获取

- P0：前端每 2 秒轮询任务详情，页面隐藏后降低频率。
- P1：增加 SSE `/pipeline/jobs/{id}/events`，实时推送阶段、日志和完成事件。

## 11. 搜索、知识库与 RAG 设计

### 11.1 检索策略

统一检索采用“关键词检索 + 语义检索 + 重排”：

1. 根据用户查询识别数据类型、时间、来源和技术方向条件。
2. 在 OpenSearch 执行标题、摘要、正文、作者、期刊、标签的 BM25 检索。
3. 对知识问答和报告生成，在 Qdrant 执行授权片段的向量检索。
4. 合并结果并使用重排模型排序。
5. 应用数据权限和版本过滤。
6. 返回可解释字段：关键词命中、高亮、共同标签或引用片段。

### 11.2 权限过滤

- 在检索请求进入搜索/向量库前计算允许的 `owner_id/dept_id/visibility/material_id` 范围。
- 不能先取回无权限正文再在前端过滤。
- 向量库 payload 包含资料版本和权限筛选字段，但最终仍需关系库二次校验。

### 11.3 切块策略

- 优先按 Word 标题、PDF 目录/页面、Markdown 标题切分。
- 单块建议 500-1000 中文字符，重叠 80-150 字；表格和标题说明作为独立语义单元。
- 每块保留：文件、版本、标题路径、页码、段落序号、原文偏移、内容哈希。
- 模板、表单字段和经费表不得与普通正文混为同一块。

### 11.4 生成防幻觉

- 先检索证据，再生成章节；证据不足时返回缺口。
- Prompt 明确禁止把无来源建议写成既有事实。
- 技术指标、金额、日期、标准号和专利数量进行规则校验。
- 生成后对每段提取事实声明并检查引用覆盖。
- 引用原文与生成段落保留快照，资料后续更新不改变历史报告证据。

## 12. Word/PDF 模板与导出设计

### 12.1 模板组成

每个报告模板包含：

- 结构 Schema：章节、字段、必填、顺序、目标字数。
- Word 模板文件：样式、封面、页眉页脚、页码、表格骨架。
- 变量映射：如 `{{requirement_name}}`、`{{section.production_need}}`。
- 表格映射：经费表、计划表、指标表、来源清单。
- 导出规则：是否目录、图形位置、附录、引用格式。
- 校验规则：必填字段、最小章节长度、金额和年份一致性。

### 12.2 导出流程

1. 锁定报告版本、模板版本、图形版本和引用快照。
2. 将结构化报告映射到 Word 模板变量和内容控件。
3. 插入真实 Word 标题、列表、表格、图形、页眉页脚和页码。
4. 经费和总计重新计算，避免前端显示值与导出不一致。
5. 生成 DOCX。
6. 使用 LibreOffice 转 PDF。
7. 渲染 PDF 页面做自动检查：页数、空白页、图片缺失、字体和表格溢出。
8. 保存导出文件、任务记录、模板版本和校验结果。

### 12.3 S1/S2 模板特殊规则

- 封面单独成页，保持单位名、报告名、字段区和年月的位置层级。
- 正文使用边框式主体区域、章节标题和页脚页码。
- 六大章节顺序固定；允许章节内容跨页，但不能把章节标题孤立在页尾。
- 经费表可跨页，重复表头，预算合计必须可见。
- 未填写经费时应输出空表或“待填写”，不能由模型随意编造金额。

## 13. 安全与合规开发清单

### 13.1 接口安全

- 所有业务 Controller 使用若依 `PreAuthDependency` 或等效权限依赖。
- 对 ID 资源执行对象级权限校验，不能只检查菜单权限。
- 生成、导出、翻译等写操作使用幂等键，防止重复点击创建多个任务。
- 限制上传、搜索、知识问答和模型接口频率。
- 外部 URL 抓取必须验证协议、域名、解析 IP 和重定向目标。

### 13.2 文件安全

- 文件名规范化，禁止路径穿越。
- 校验扩展名、MIME、魔数和大小。
- 文件哈希去重但不能跨权限域错误共享。
- 对象存储桶默认私有，下载使用短期签名 URL。
- 删除采用软删除和延迟清理；有报告引用的文件不得直接物理删除。

### 13.3 AI 安全

- 系统 Prompt 与用户输入分层，不拼接成不可区分字符串。
- 上传内容视为不可信数据，明确包裹为引用材料。
- 过滤材料中的“忽略系统指令”等注入文本，不允许调用未授权工具。
- 模型输出经过 JSON Schema 或结构校验后再入库。
- 关键配置和密钥不进入 Prompt、日志和前端响应。

### 13.4 审计

必须记录：登录、失败登录、资料上传/下载/删除、权限修改、数据源修改、采集执行、人工数据修正、任务创建/取消/重试、章节生成/替换、版本恢复、报告共享、导出和模型配置变更。

| 第 12-13 周 | 采集稳定化 | 日报周报页面 | 日报周报生成和计划 |
| 第 14-15 周 | 数据验收 | 全流程联调 | AI 质量与模板修复 |
| 第 16-17 周 | 缺陷修复 | 培训/验收演示 | 性能、恢复、交付 |

压缩计划成立的前提：第 2 周前拿到客户模板、首批来源、关键词、分类标准、服务器和模型接口；翻译、OCR、自学习和复杂 PDF 保版必须延期到 P1/P2。

## 16. 研发任务拆分建议

### Epic E1：账号与双端壳层

- PortalLayout、登录浮窗、路由守卫、用户端菜单过滤、后台入口隔离。
- 验收：用户端无后台菜单，深链登录后正确返回。

### Epic E2：数据采集与治理

- 数据源/规则/试采/任务/日志、原始数据、抽取、去重、标签、质量。
- 验收：至少 3 类来源形成稳定样例数据。

### Epic E3：资讯/论文/搜索

- 资讯文章与论文分域存储，分别支持全文检索、列表/详情/筛选、论文元数据和版权状态。

### Epic E4：资料与知识库

- 文件上传、对象存储、解析、权限、资料篮、知识问答和引用；向量切块待检索服务真正上线后再单独设计。

### Epic E5：科研报告

- 任务、模板、大纲、生成阶段、编辑、引用、版本、质量检查和经费表。

### Epic E6：图形与导出

- 节点图编辑、版本、PNG/SVG、DOCX/PDF 模板导出和渲染检查。

### Epic E7：日报周报

- 手动/自动任务、候选筛选、模板栏目、编辑、来源清单和导出。

### Epic E8：后台支撑

- 模板、模型、Prompt、操作日志、监控、备份和恢复。

## 18. 原型验收检查表

- 登录浮窗默认关闭，点击后居中打开。
- 用户端没有任何后台管理菜单或后台侧栏。
- 一级导航只有六项，不重复出现多个工作台。
- 资讯和公众号统一呈现但能按来源类型区分。
- 论文不可用全文时有清晰版权状态。
- 新建报告采用步骤流程，不是一个超长表单。
- 报告编辑器能看到章节、引用、质量和版本。
- 科技项目需求填报表包含封面、六大章节和经费表。
- 日报周报显示来源清单且每条内容可追溯。
- 知识问答的引用能定位资料页码或章节。
- 管理端和用户端视觉与权限边界清晰。
- 所有页面有加载、空、错、权限和任务状态。
