## 8. 早期业务数据库创建示例（已废弃，禁止用于 `pipeline_news.news`）

### 8.1 原设计目标（仅供历史参考）

```
news 正文表 —— 按月分区，分区键 pub_date
  ├── 0~3 个月：ts_hot（NVMe/SSD）
  └── >3 个月：ts_cold（HDD）
  正文永久保留，不删除

news_embedding 向量表 —— 关联 news
  向量数据永久保留，不删除
```

### 8.2 创建主表

以 superuser 身份连接到 newsdb：

```sql
-- ============================================
-- 新闻正文表：按月分区
-- ============================================
CREATE TABLE news (
    id          bigint GENERATED ALWAYS AS IDENTITY,
    title       text NOT NULL,
    content     text NOT NULL,
    source_url  text,
    pub_date    timestamptz NOT NULL,   -- 分区键
    created_at  timestamptz DEFAULT now()
) PARTITION BY RANGE (pub_date);

-- 分区键索引（自动继承到所有子分区）
CREATE INDEX ON news (pub_date);

-- ============================================
-- 向量表
-- ============================================
CREATE TABLE news_embedding (
    id          bigint GENERATED ALWAYS AS IDENTITY,
    news_id     bigint NOT NULL REFERENCES news(id),
    embedding   halfvec(768) NOT NULL,  -- 维度按实际模型调整
    created_at  timestamptz DEFAULT now()
);

-- HNSW 索引加速向量相似度检索
CREATE INDEX ON news_embedding USING hnsw (embedding halfvec_cosine_ops);
```

### 8.3 pg_partman 接管分区

```sql
-- 按月自动创建分区，提前建 4 个月
SELECT partman.create_parent(
    p_parent_table   := 'public.news',
    p_control        := 'pub_date',
    p_type           := 'native',
    p_interval       := '1 month',
    p_premake        := 4,
    p_start_partition := '2026-07-01'
);

-- 新分区默认建在热盘
UPDATE partman.part_config
SET tablespace = 'ts_hot'
WHERE parent_table = 'public.news';
```

### 8.4 冷热分区迁移（pg_cron 定时任务）

```sql
-- 每天凌晨 3 点：把超过 3 个月的分区从 ts_hot 迁移到 ts_cold
SELECT cron.schedule(
    'migrate-news-to-cold',
    '0 3 * * *',
    $$
    DO $$
    DECLARE
        rec record;
        cutoff timestamptz := date_trunc('month', now()) - interval '3 months';
    BEGIN
        FOR rec IN
            SELECT tablename
            FROM pg_tables
            WHERE schemaname = 'public'
              AND tablename LIKE 'news_p%'
              AND tablename ~ '^news_p\d{4}_\d{2}$'
        LOOP
            -- 解析分区名中的日期判断是否超 3 个月
            -- 超 3 个月且还在 ts_hot → 迁移到 ts_cold
            EXECUTE format(
                'ALTER TABLE %I SET TABLESPACE ts_cold',
                rec.tablename
            );
        END LOOP;
    END $$;
    $$
);
```

> **注意**：上面的 cron 迁移逻辑是骨架代码，每次全量扫描分区。生产环境建议按 `tablename` 中的日期后缀精确判断 `cutoff`，避免每个分区都执行 ALTER。

    apt-get update; \

      "postgresql-18-cron=${PG_CRON_DEB_VERSION}" \

    test "$(dpkg-query -W -f='${Version}' postgresql-18-pgvector)" = "${PGVECTOR_DEB_VERSION}"

## 12. 注意事项

- **Docker 镜像拉取**：服务器通过代理 `172.16.4.140:7890` 访问外网。拉取 Docker 镜像时需通过 `--build-arg` 传入代理，或使用国内镜像源（如华为云 SWR）
- **端口安全**：5432 端口已绑定 `0.0.0.0`，需配合防火墙白名单使用
- **旧脚本兼容**：仓库中旧脚本 `setup_news.sql` / `setup_hot_cold.sql` 使用 `ts_ssd/ts_hdd` 命名，与当前 `ts_hot/ts_cold` 不兼容，不要直接执行
- **向量保留策略**：当前设定向量数据永久保留，不再执行 13 个月过期删除
