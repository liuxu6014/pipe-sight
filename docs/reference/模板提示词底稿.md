# 模板提示词底稿

本文件把 `docs/reference/` 下的三份模板结构化，提炼为可直接配置到后台 `templates.prompt` 的提示词底稿。用于指导大模型生成对应报告类型，管理员可在此基础上增删约束。

---

## 一、科技项目需求填报表（`project-demand`）

来源：`技术需求模板及撰写指南.doc`（撰写指南）+ `文本生成示例.docx` / `文本生成示例2.docx`（填写样例）。

### 输出结构

```
国家石油天然气管网集团有限公司
科技项目需求填报表

需求名称：…
需求级别：集团级 / 企业级
需求类别：开发研究 / …
需求类型：业务导向型 / …
技术业务域：AW安全与维护 / …
技术图谱子技术：…
研究起止时间：…年…月至…年…月
填报单位：…
联系人：…　　联系方式：…
日期

一、生产需求及技术问题
二、国内外技术现状分析
三、研究目标
四、研究内容
五、预期研究成果
六、经费需求（预算科目表）
```

### 各章节撰写要求

**一、生产需求及技术问题**
围绕选题说明背景和原因，回答立项的必要性与紧迫性。生产需求通常包括三类：
1. 安全生产需要、解决生产问题（如打孔盗油、泄漏监测）。
2. 因技术/产品受限开展的引进消化吸收再创新或设备国产化研究。
3. 技术服务、技术集成等推广应用类研究。
理论创新或前瞻性研究说明如何与科研院所/院校合作获取成果储备。

**二、国内外技术现状分析**
围绕选题做科技与专利文献检索、调研、查新。逐层展开：
- 集团公司研究基础；
- 国内技术现状；
- 国外技术现状；
- 分析结论。

要回答：目前谁在研究？进展与成果？能否为我所用？技术优劣势？本项目解决什么问题、独到之处在哪？内容取自查新报告、专利检索、论文与已有成果，避免冗繁堆砌历史，也避免缺失现状分析。

**三、研究目标**
写清要达到的具体目的、要解决的具体问题。目标要明确具体；每个研究目标至少对应一项成果。主体内容与技术性能、技术经济、效益、知识产权对应。

**四、研究内容**
为实现目标需完成的具体工作任务，紧扣目标层层分解。可按课题/专题归类，或按总体设计→原理→试验→推广过程分解，或混合分解。避免：内容笼统只写标题、与研究目标关联不强、目标/内容/指标概念混淆、重点不突出。每项研究内容之和即研究的实物工作量。

**五、预期研究成果**
预测成果的属性、形式、名称、数量。属性：新技术/新工艺/新材料/新产品/软科学/装备。形式：知识产权（专利/技术秘密/软件）、样机/样品、中试装置、工艺方法、标准规范、操作手册、配方、论文、专著、研究报告。避免把研究内容照抄或把预期成果当作关键技术。

**六、经费需求**
按预算科目表列出，分为资本化预算（设备费/软件购置费/其他）与费用化预算（材料费、试验检验费、委托研发支出、劳务费等 24 项），并给出预算合计与分年度金额。

### 格式要求
- 节标题用加粗（`**标题**`），条目标题用普通文本，不使用 Markdown 的 `#` 号。
- 引用库内资料时用 `[n]` 标注，正文末尾列出参考资料。
- 输出可直接呈现的 Markdown 正文。

## 二、科技情报日报（`daily`）

来源：`生物安全日报示例.docx`（样例）。周报/月报结构相同，仅覆盖周期不同。

### 输出结构

```
{报告名} {日期}

一、引言

{类别一}
{条目1：标题 + 正文摘要 + 发布时间 + 洞察 + 数据源}
{条目2：…}

{类别二}
…

参考资料
[1] …
[2] …
```

### 条目格式（每个类目下）

每个条目包含四部分：
1. **标题**：一句话概括该条情报。
2. **正文摘要**：2–4 句，交代事件/进展的时间、主体、事实与影响。
3. **洞察**：以「{领域}洞察：」开头，给出 1–2 句分析（对安全/行业的影响、风险或意义）。
4. **数据源**：`[n] 标题【来源】`，对应文末参考资料。

### 分类与选材
- 类目（分节标题）由模板配置的类别决定，示例使用生物安全类目（实验室生物安全、重大传染病防控、政策法规、国际合作与治理、战略与体系建设、农业生物安全、动植物疫情防控、疫苗与生物防御、新兴技术安全）。
- 条目按类别聚合；同一事件的多语言/多来源报道合并为一条，用多个 `[n]` 标注。

### 格式要求
- 节标题（引言 / 各类目 / 参考资料）用加粗（`**标题**`），不使用 Markdown 的 `#` 号。
- 数据源引用 `[n]` 与文末参考资料一一对应。
- 输出可直接呈现的 Markdown 正文。
