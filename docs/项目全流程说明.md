# 国家管网科技情报与科研辅助平台 · 项目全流程说明

> 本文面向管理层，用一条完整链路讲清楚：平台采集什么数据、怎么处理、最终产出什么成果。
> 面向研发的技术细节见 [architecture/pipeline-flow.md](architecture/pipeline-flow.md)。

---

## 一、平台定位

面向国家管网科技创新的**科技情报与科研辅助平台**。它把分散在公开网络上的三类科技情报
（**新闻网站、微信公众号、学术论文**）自动汇聚、统一处理、结构化入库，再结合大模型自动
生成**科技情报简报**与**科研报告**，并为科研人员提供**资料库**与**科研任务**管理能力。

一句话：**情报自动进得来、处理得干净、成果出得来。**

---

## 二、全流程总览

```
   ① 数据采集                 ② 统一处理             ③ 入库           ④ 应用                ⑤ 成果

 新闻网站 ─┐
 微信公众号 ─┼──▶ 统一汇聚(Kafka) ──▶ 翻译 / 分类 / 有效性校验 ──▶ PostgreSQL ──▶ 情报浏览 · 检索 ─┬─▶ 科技情报简报
 论文(Crossref)┘                                                        (统一库)                  └─▶ 科研报告
                                                                                                   │
 内部资料 ──────────────────────────────────────────────────────────────▶ 资料库 ──▶ 科研任务 ──▶ 成果导出
```

五个环节闭环运行：采集 → 处理 → 入库 → 浏览/选材 → 生成成果。

## 三、各环节说明

### ① 数据采集：三路来源，管理员全程可控

| 来源 | 采集方式 | 说明 |
| --- | --- | --- |
| **新闻网站** | 站内定时采集 | 定时抓取国家管网官网等公开新闻 |
| **微信公众号** | 公众号 RSS 链接 | 管理员在「数据源管理」中添加公众号的 RSS 链接，平台定时拉取 |
| **学术论文** | 站内定时采集 | 从 Crossref 等公开渠道抓取论文（默认摘要，全文按授权获取） |

管理员能力：**新增 / 启停采集源、添加公众号 RSS 链接、设置采集周期、手动立即采集、查看运行状态**。

### ② 统一处理：进来的数据先"过一遍筛子"

所有采集到的内容都经过同一条处理流水线，再决定是否入库：

1. **统一接入**：外部爬虫采集的内容统一经消息队列（Kafka）进入平台，与站内采集汇入同一条流水线；
2. **翻译**：来源配置了翻译模型时，把外文正文/摘要翻译成中文；
3. **分类**：按管理员维护的类别（提示词 + 模型）自动归类；
4. **有效性校验 + 去重**：标题/链接/DOI 非法、重复的内容一律不入库，只保留"有效数据"。

### ③ 统一入库

处理后的有效内容统一写入一个 PostgreSQL 数据库（`public` 库），三类内容共用一套紧凑的内容契约，便于统一检索与选材。

### ④ 情报浏览与检索

用户在门户端按 **新闻 / 公众号 / 论文** 三类浏览、关键词检索、查看详情（标题、时间、正文、类别、作者、原文链接）。

### ⑤ 成果生成：两类成果，独立管理

| 成果类型 | 内容 | 生成方式 |
| --- | --- | --- |
| **科技情报简报** | 日报 / 周报 / 月报 | 按自动简报计划定时选材，模板 + 大模型自动生成 |
| **科研报告** | 科技项目需求填报、科研需求报告、技术路线报告 | 从情报/资料中选材，套用模板 + 大模型生成 |

> 两类成果在平台中独立存放、独立管理，不互相混入。

### ⑥ 资料库与科研任务

- **资料库**：上传、解析内部资料，授权访问，把研究资料加入"资料篮"；
- **科研任务**：从资料篮创建任务，执行资料处理、结果审核、重试/驳回，导出成果。

## 四、管理员能力清单

| 模块 | 能力 |
| --- | --- |
| 情报工作台 | 有效资讯统计、采集状态、热点主题、待审核报告概览 |
| 数据源管理 | 新增/启停采集源、添加公众号 RSS 链接、设置采集周期、手动采集 |
| 采集任务 | 任务列表、运行状态、进度、手动触发/停止 |
| 类别 / 过滤 | 维护内容类别与过滤规则，自动分类与预过滤 |
| 模型 / Prompt | 配置文本/图片模型、Prompt 模板、场景路由 |
| 模板管理 | 维护简报与报告模板 |
| 简报计划 | 配置日报/周报/月报的自动生成计划 |
| 报告管理 | 查看/导出报告（Markdown / DOCX / PDF） |
| 系统管理 | 用户 / 角色 / 菜单 / 字典 / 参数 |
| 监控管理 | 在线用户、操作日志、登录日志、定时任务、服务/缓存监控 |

## 五、系统架构（简表）

| 层级 | 技术 |
| --- | --- |
| 前端（门户 + 管理端） | Vue 3 + Element Plus |
| 后端 | FastAPI（异步） |
| 数据库 | PostgreSQL（统一库） |
| 消息队列 | Kafka（统一采集接入） |
| 缓存 | Redis |
| 任务 Worker | 定时采集、简报派发、报告导出、资料解析 |
| AI / 大模型 | 多模型接入（翻译、分类、简报/报告生成） |

## 六、当前进展与边界

**已具备**：三路采集（含公众号 RSS）、统一处理入库、情报浏览/检索、科技情报简报、科研报告、
资料库、科研任务、管理员全套管理能力。

**仍在推进**：生产级来源接入按来源逐一验收；语义检索、Elasticsearch/Milvus 等增强能力为可选项，
需完成验收后再宣称交付；备份恢复、容量压测、告警接入等生产化事项按计划补齐。

> 具体功能项、需求问题与业务场景，见 `docs/requirements/` 下的需求核对文档。
