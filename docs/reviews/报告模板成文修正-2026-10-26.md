# 报告模板成文修正

## 范围与原因

报告 40 使用模板 31「科技项目需求填报表」。旧提示词为章节配置 JSON，六章默认目标共 10400 字；仅有五条新闻及论文摘要资料，实际正文大量重复资料边界、待论证说明与通用建议，还将新闻引用挂在预算原则等不受该新闻支持的论述后。

本次修正模板和后续生成规则，不覆盖历史报告，不变更表结构，不操作若依表，不修改模型凭证。

## 调整

- 模板提示词改为正式的项目需求报告写作要求，仍保留原六章，不擅自改成其他文章体裁。
- 默认篇幅依次为 800、1000、500、900、500、150 字，合计 3850 字，可由用户确认大纲时调整。篇幅是参考规划，不以凑字或编造满足目标。
- 新建页面预计篇幅随实际大纲合计，不再固定显示 8000–12000 字；章节字数允许小于 500 字，避免经费短章被输入组件强制加长。
- 六章分别负责需求与问题、技术比较、目标、研究路径、交付成果、经费依据；不重复复述同一材料。
- 没有经费依据时简短说明测算前提，不虚构金额或扩写通用财务制度。
- 生成规则约束自然段论证、章节衔接、事实与建议的区别，以及引用与事实的对应关系；保留句末引用、连续编号和现有页面/导出排版链路。
- 历史结构 JSON 的章节独立传入大纲，显式的管理员写作文本保留，不将整份 JSON 作为写作指令。简报不套用长文论证规则。
- 旧测试要求不会被偷偷删除；报告 40 及其冻结任务参数保留原样。新一轮生成应使用正常业务要求，而非复制旧的“句末引用验证”测试说明。

## 验证边界

回归测试检查真实模型调用参数中存在成文、字数、引用规则，旧 JSON 已分离，管理员提示词保留，冻结配置不被改写；同时运行现有生成、元数据、模板和报告相关测试。

验证结果：后端相关测试 115 通过、6 跳过；本次新增文件 Ruff 检查通过；前端 430 项测试全部通过，生产构建通过，`git diff --check` 通过。确认无正在执行的生成任务后重启本项目 API（19099）和任务执行器；新建报告实际页面已读到修改后的模板说明及「按大纲规划（约 3,850 字）」。截图位于 `output/ui-optimization-20261026/报告模板修正.png`。用户当前报告页未被导航或覆盖。

这些测试证明规则进入生成链路，不等于已验收大模型的实际新正文。本次没有调用外部模型生成新报告，没有覆盖报告 40，也没有产生新的 Word/PDF；页面和导出仍沿用已有排版实现，后续新报告需要再次逐段检查引用支撑和成文质量。
