# 管网科技情报平台设计

日期：2026-07-13

## 背景

本项目首期采用 `insistence/RuoYi-Vue3-FastAPI` 作为全栈底座。该项目是社区维护的若依 Vue3 + FastAPI 版本，提供登录、JWT、角色、菜单、按钮权限、审计日志、动态路由、代码生成和基础监控能力。

现有 `frontend/dayReport-web` 是构建后的静态产物，不包含可维护的 Vue 源码。迁移策略是保留该产物作为视觉和交互参考，重新搭建 Vue3 源码项目，并把业务页面接入若依的认证、权限和菜单体系。

## 业务定位

根据 `docs/requirements/设计方案.docx` 和 `docs/requirements/平台功能需求分析与进度规划.pdf`，本项目不是传统管线台账、巡检或 GIS 系统，而是面向国家管网科技创新场景的“科技情报与科研辅助平台”。

首期目标是形成最小业务闭环：

- 若依登录、用户、角色、菜单和操作日志。
- 新闻、公众号、论文的采集任务与数据源管理。
- 资讯列表、论文列表、详情页、统一检索和筛选。
- 日报周报页面骨架与样例数据。
- 知识库问答、报告生成、技术路线图等能力先搭菜单和页面骨架。

## 架构方案

采用单体模块化方案起步：

- `frontend/`：Vue3 + Vite + Element Plus，保留若依管理端 Layout、权限指令、动态路由和菜单加载。
- `backend/`：FastAPI + SQLAlchemy，保留若依后端用户、角色、菜单、日志、字典、定时任务等基础模块。
- `frontend/legacy-static/`：保留旧静态演示产物，作为拆页和验收对照。
- PostgreSQL/MySQL、Redis 沿用若依配置。Elasticsearch、MinIO、Milvus、Kafka 暂不在首期强制启用，只预留菜单和接口边界。

选择这个方案的原因是风险最低：若依底座保持完整，业务页面按模块插入，不破坏认证和权限主链路。

## 前端页面

一级菜单建议命名为“管网情报”。首期页面包括：

- `管网情报 / 工作台`：情报概览、采集状态、热点主题、待审核报告。
- `内容检索 / 新闻资讯`：新闻列表、来源、标签、相关性、状态筛选。
- `内容检索 / 公众号文章`：公众号文章列表和详情入口。
- `内容检索 / 论文跟踪`：论文列表、方向、期刊会议、引用趋势。
- `数据采集 / 数据源管理`：来源名称、类型、频率、状态、最后采集时间。
- `数据采集 / 采集任务`：任务列表、运行状态、成功率、错误信息。
- `智能生成 / 日报周报`：日报、周报、审核状态和导出入口。
- `智能生成 / 报告生成`：技术路线报告、科研需求报告页面骨架。
- `知识库 / 文档库` 与 `知识库 / 智能问答`：先搭入口和空状态。

视觉采用专业后台风格：白底、浅灰分区、管网蓝为主色、橙色用于重点操作和风险提示。页面避免营销式大 Hero，优先保证表格、筛选、详情和审核流程易扫读。

## 后端模块

新增业务模块建议命名为 `module_pipeline`，前缀为 `/pipeline`。

首期数据对象：

- `IntelligenceItem`：统一承载新闻、公众号、论文条目。
- `DataSource`：新闻源、公众号、论文库等来源配置。
- `CollectTask`：采集任务和运行状态。
- `ReportDraft`：日报周报与报告草稿。

首期接口先提供模拟业务数据，保证前端菜单、权限和页面流程跑通。后续再接真实采集、清洗、去重、实体抽取、搜索索引和 RAG。

## 权限菜单

权限编码按若依习惯设计：

- `pipeline:dashboard:view`
- `pipeline:intel:list`
- `pipeline:intel:query`
- `pipeline:intel:detail`
- `pipeline:source:list`
- `pipeline:source:edit`
- `pipeline:task:list`
- `pipeline:task:run`
- `pipeline:report:list`
- `pipeline:report:export`
- `pipeline:kb:view`

菜单可通过若依后台录入，也可用初始化 SQL 导入。首期代码内先提供页面和接口，菜单数据后续由系统管理模块维护。
