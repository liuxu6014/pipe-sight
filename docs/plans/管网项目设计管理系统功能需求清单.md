## 4. 数据采集与处理

### 4.1 爬虫管理

- 系统应统一展示和管理 100 个以上现有新闻、公众号及其他定向数据源爬虫。
- 爬虫列表应展示：爬虫编号、爬虫名称、来源名称、来源类型、目标地址、所属技术方向、启用状态、运行状态、调度周期、最近执行时间、下次执行时间、最近采集数量、连续失败次数和最近失败原因。
- 支持按名称、来源类型、技术方向、启用状态和运行状态检索或筛选爬虫。
- 支持对单个爬虫设置“启用爬取 / 停止爬取”，并支持勾选多个爬虫批量启用或停用。
- 停用后的爬虫不得再被定时任务触发；重新启用后按配置的调度周期恢复执行。
- 支持为现有爬虫配置执行周期、执行时间、超时时间、重试次数、请求频率和并发限制。
- 支持查看单个爬虫的执行历史、采集数量、成功率、耗时和错误日志。
- 爬虫启停和配置修改应记录操作人、操作时间、修改前后内容和操作结果。
- 爬虫管理和启停操作应受角色权限控制。
- 本期只管理和配置已经接入的爬虫，不提供用户自行新增、开发或接入新爬虫的功能。

### 4.3 新闻处理规则配置

- 管理员可直接在后台配置新闻数据的过滤、分类和评分规则，无需修改程序代码。
- 处理流程统一为：原始数据接入 -> 过滤 -> 去重 -> 分类 -> 评分 -> 自动发布或进入人工复核。
- 过滤规则支持配置：来源白名单 / 黑名单、包含关键词、排除关键词、技术方向、行业范围、语言、发布时间范围、正文最小长度、正文完整性和业务相关度阈值。
- 支持设置过滤规则名称、规则组、优先级、启用状态、命中条件、处理动作和生效时间。
- 过滤处理动作至少包括：保留、丢弃、标记待复核和降低优先级。
- 分类体系支持多级分类，至少包含行业分类、技术方向、资讯类型和主题标签；分类层级、分类名称和启用状态可配置。
- 分类规则支持按来源、关键词、命中条件或模型识别结果将新闻归入一个或多个分类。
- 评分规则支持配置评分维度、权重、分值范围、等级阈值和启用状态。
- 评分维度至少包括：业务相关性、技术价值、来源权威性、时效性、行业影响力和内容完整度。
- 新闻总分及等级由评分规则自动计算；评分等级名称和阈值可配置，例如“重要 / 较重要 / 一般 / 低价值”。
- 支持按评分等级决定后续动作，例如自动发布、进入人工复核、仅入库或丢弃。
- 规则配置应支持保存草稿、启用、停用、调整优先级和版本留痕。
- 支持使用历史新闻对规则进行命中测试，预览过滤结果、分类结果、各维度得分、总分和等级后再启用。
- 每条新闻应保存命中的规则、分类结果、评分明细、总分、等级、处理状态和处理时间，便于追溯。
- 授权人员可人工调整新闻分类、评分等级和发布状态；人工调整应记录原因及操作日志。

## 8. 验收指标与阶段目标

- 首期形成采集 -> 处理 -> 展示的最小闭环
- 每个技术方向每周期不少于 20 条有效资讯
- 去重误判率低于 5%
- L1 大类分类准确率不低于 85%
- 爬虫管理页面可稳定加载并管理 100 个以上爬虫，支持筛选及批量启停。
- 停用爬虫后不再产生新的定时采集记录，重新启用后可按调度配置恢复执行。
- 新闻过滤、分类和评分规则修改后无需发版即可生效，并保留完整版本及操作记录。
- 新闻处理结果可追溯至命中的过滤规则、分类规则及各评分维度。
- 报告人工审核量不超过总篇幅的 30%
- 阶段性交付 API 文档、前端指南、容器化部署包

## 9. 角色边界

- 用户端只显示新闻 / 论文 / 日报周报 / 知识库 / 科研辅助相关能力
- 管理端保留 RuoYi 的系统管理能力
- 用户端不暴露系统管理、系统监控、系统工具、AI 管理、个人中心、后台登录入口
