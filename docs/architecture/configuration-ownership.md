# 配置主来源与处理边界

本文件区分当前实现与长期目标，不把命名整理描述成全量提示词整合已完成。

## 管理责任

| 内容 | 当前存储 | 管理与执行责任 |
| --- | --- | --- |
| 模型、接口、密钥 | public.ai_models | 唯一模型配置主来源，复用若依管理接口；密钥不进入处理消息和普通调用日志 |
| 场景主备模型、超时、限额 | public.model_routes | 只引用已有模型，不复制另一套服务商凭据 |
| 每日模型路由用量 | public.model_route_usage | 配额计数，不是配置项，不与调用明细合并 |
| 单次调用结果 | public.model_calls | 记录模型、耗时、错误和版本标识，用于审计，不是模型配置 |
| 应用场景提示词 | public.prompt_versions | 管理员维护、离线结构测试和发布；实际任务固定使用快照 |
| 报告/简报模板 | public.template_versions | 章节、输出格式与版本；不是提示词版本的别名 |
| 历史处理提示词及血缘 | news.prompt_versions、news.prompt_usages | 保留既有版本和引用；尚未成为所有处理步骤的统一配置来源 |
| 历史领域内嵌提示词 | news.domains.filter_prompts、score_prompts | 兼容动态领域处理路径，尚不能删除 |
| 分类标准 | news.domain_topic_rules.category_prompts、prompt_version_id | 当前查询只消费非空内嵌分类标准；仅有版本引用的配置未完整接入读取，属于待修复边界 |

## 当前数据过滤路径

平台采集侧生成过滤提示词快照并随交接记录传递，动态领域过滤器 `_llm_filter` 检测到该快照时优先使用快照及场景模型路由，内部代理调用记录相应应用提示词版本ID。没有平台快照的历史输入仍可能走领域内嵌或本地处理器配置。

因此不能简单断言“管理员发布的过滤提示词完全没有使用”，也不能断言“所有分类和评分已经统一读取管理员配置”。两者是不同的执行路径。

## 长期收敛目标（尚待实施）

1. 以应用侧 `public.prompt_versions` 作为管理员提示词配置的主来源。过滤、分类、评分等阶段必须有明确场景和变量约定；扩展场景需要同步UI、权限、校验和Worker，不能只增加数据库字段。
2. 新任务生成时固定版本ID、内容摘要、变量约定及正文快照；执行过程中不查询“最新版本”覆盖已有任务。重试复用原快照，切换配置必须作为新执行记录留痕。
3. 处理器明确区分平台快照输入和历史兼容输入，禁止在配置缺失时静默切换另一套提示词并仍声称使用管理员配置。
4. 处理侧若保留投影或血缘，必须保存应用版本映射及内容摘要。当前应用版本ID为字符串，历史处理版本ID为bigint，不能强行等同或裸改外键。
5. 旧版本引用、内嵌文本和新版本内容先做只读盘点及冲突清单，再决定迁移。没有完成映射、回归、回滚验证前，不删除历史表或列。
6. 分类规则的版本引用读取、发布版本保护和并发发布约束需单独实现和验证。本轮没有将这些待办伪装为已经完成。

## 保留的合理分表

- 质量问题保存当前状态，`quality_issue_events` 保存状态变更历史。
- 重复组保存治理对象，成员表保存关联，`duplicate_group_events` 保存人工决定。
- 内容审核状态保存在内容表，`content_review_events` 保存审核过程。
- 报告当前版本、历史版本、发布记录、导出任务具有不同生命周期，不为追求表少而合并。

## 日期与时间

模型路由配额目前按业务代码中的当日零点计数，`usage_date` 仍为DateTime。本轮不改字段类型或时区。后续转为Date前须核对实际写入时间、已有非零点值、统计时区以及同日记录冲突；以事务迁移和配额并发测试验证，不能仅修改ORM类型。
