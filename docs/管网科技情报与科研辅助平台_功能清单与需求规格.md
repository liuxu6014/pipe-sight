# 管网科技情报与科研辅助平台：功能清单与需求规格

> 文档用途：需求确认、产品范围冻结、原型设计输入、研发任务拆分、测试用例设计和项目验收。
>
> 版本：V1.0（根据 5 份客户材料与当前代码结构整理）  
> 编制日期：2026-08-04  
> 适用项目：`D:\A_CODEBASE\pipeSight`

## 1. 文档结论

平台应定位为一个面向管网行业科研和技术情报人员的“科技情报检索 + 科研资料沉淀 + AI 报告生成 + 日报周报”的业务平台，而不是把若依后台管理页面直接提供给普通用户。

一期产品范围应以四条业务主线组织：

1. 科技资讯与论文：采集、清洗、分类、检索和查看新闻、微信公众号文章、论文元数据。
2. 科研资料库：上传、解析、检索和授权使用内部文献、英文报告、论文和历史项目资料。
3. 科研材料生成：按客户模板生成科技项目需求填报表、科研需求报告、技术路线报告及配套图形。
4. 日报周报：基于指定时间范围、来源和技术方向生成日报、周报，并保留来源清单。

普通用户端必须登录鉴权，但只能看到业务功能；用户端不得出现“系统管理、系统监控、系统工具、AI 管理”等后台菜单。用户、角色、日志、数据源、采集任务、模板、模型等管理能力保留在独立的管理员控制台中。

### 2.3 材料中的冲突与统一口径

1. 新闻与微信公众号：S4 分别列出，S3 明确两者统一按“资讯”处理。系统统一使用 `content_type=news`，通过 `source_type=website/wechat` 区分；前端可使用页签和筛选器呈现。
2. 用户端与后台：S3/S4 要求后台用户、角色、日志能力，但普通用户端不应显示后台菜单。统一为“双壳层”：用户业务门户 + 若依管理员控制台。
3. 报告类型：S4 重点为技术路线和科研需求；S1/S2 实际展示的是“科技项目需求填报表”。一期至少提供三种模板：科技项目需求填报表、科研需求报告、技术路线报告。
4. 图形输出：S3 写“方案图”，S4 明确概念图、思维导图、技术路线图。统一为三种可选图形类型，并支持节点级编辑和重新生成。
5. 论文全文：S3 明确 WOS 等受版权限制的全文不可直接爬取。系统默认只采集合法元数据和摘要；全文只能来自开放访问来源或用户有权上传的文件。
6. 会议日期：`6.9第一次会议(1).docx` 文件名、表内日期“2025 年 9 月 13 日”和调研对象“华大基因”不一致，疑似复用模板。只采纳其中功能条目，不把日期和调研对象作为项目事实。
7. 进度：S4 给出 24 周计划及 2026-11-30 前交付。以当前日期 2026-08-04 计算，若尚未开始，剩余时间不足 24 周，必须采用压缩并行计划或缩减范围。

## 3. 产品定位与业务目标

### 3.1 产品名称

建议统一使用：国家管网科技情报与科研辅助平台。

### 3.2 目标用户

- 管网科技情报人员：检索、筛选、收藏和研判行业资讯。
- 科研项目人员：管理资料，生成科研需求、技术路线、开题或申报材料。
- 业务专家/审核人：审核标签、报告内容、技术指标和来源引用。
- 数据运营人员：维护数据源、采集规则、分类标签和数据质量。
- 系统管理员：维护用户、角色、权限、日志、模板和模型配置。

### 3.3 核心问题

- 科技资讯、论文、内部材料分散，缺少统一入口。
- 依靠人工浏览和筛选，信息发现效率低。
- 新闻、公众号和论文缺少统一分类、标签和来源追溯。
- 科研需求、技术路线和日报周报重复编写，模板化程度低。
- 生成式 AI 缺少资料边界、来源引用、版本管理和人工复核闭环。

### 3.4 业务价值指标

以下为建议指标，最终值需由客户确认：

| 指标 | 建议目标 |
| --- | --- |
| 资讯检索时间 | 相比人工跨站检索降低 60% 以上 |
| 日报初稿整理时间 | 从小时级降低到 10 分钟以内 |
| 科研需求报告初稿时间 | 从数天降低到 30 分钟以内 |
| 数据字段完整率 | 首批正式数据不低于 98% |
| 采集任务成功率 | 稳定数据源不低于 95% |
| 重复内容占比 | 清洗后不高于 2% |
| 报告模板结构完整率 | 100% 包含规定章节和必填字段 |
| 来源可追溯率 | 生成内容中的事实性要点应可回溯到来源材料 |

## 4. 范围优先级

### 4.1 P0：一期必须交付

- 用户端登录、退出、会话续期、忘记密码/管理员重置密码。
- 用户门户首页、统一检索、资讯列表/详情、论文列表/详情。
- 新闻网站、公众号、论文元数据的数据源维护和采集任务。
- 数据清洗、去重、正文抽取、摘要、分类、标签和人工修正。
- 内部资料上传、解析、权限控制、检索、查看和任务引用。
- 科技项目需求填报表、科研需求报告、技术路线报告生成。
- 报告章节编辑、局部重新生成、版本保存、来源引用和 Word/PDF 导出。
- 概念图、思维导图、技术路线图生成、编辑和导出。
- 日报/周报手动创建、自动计划、编辑、来源清单和 Word/PDF 导出。
- 用户、角色、菜单/按钮权限、数据权限、操作日志。
- 模板管理、文件存储、模型配置、Prompt 版本和基础备份。

### 4.2 P1：一期增强或二期前半段

- 热点主题聚类、热度趋势、重点新闻评分和日报自动引用。
- Word、Markdown、TXT 文件翻译；可解析 PDF 的纯文本翻译。
- 论文引用格式导出（GB/T 7714、APA、BibTeX 等）。
- 论文/综述草稿生成，与现有 manuscript 原型整合。
- 报告审核流、批注、退回修改和部门级共享。
- 订阅、收藏、稍后阅读、关键词预警和站内通知。
- 新闻图片本地缓存、图片版权标记和图片失效回退。
- 外部系统 API 调用、回调通知和导出下载中心。

### 4.3 P2：后续扩展

- 扫描纸质书 OCR、版面识别、人工校对后进入知识库。
- 保留复杂排版的 PDF 翻译。
- 生图模型生成概念插图或报告封面。
- 在线学习、自学习模型更新和自动参数优化。
- 统一身份认证、LDAP、OIDC 或集团单点登录。
- 多组织、多租户、跨单位资料授权。
- 专用移动端或小程序。

### 4.4 明确不在默认一期范围

- 绕过版权或访问控制爬取论文全文。
- 在普通用户端暴露若依的系统管理、监控、工具和 AI 配置菜单。
- 在无客户模板、无指标定义的情况下承诺生成内容一次性可直接报批。
- 未经人工复核自动更新生产模型或自动对外发布报告。

## 5. 用户角色与权限矩阵

### 5.1 建议角色

| 角色 | 主要职责 | 默认数据范围 |
| --- | --- | --- |
| 普通业务用户 | 浏览资讯/论文、使用个人资料、创建报告和日报周报 | 公共数据 + 本人资料 + 本人报告 |
| 科研用户 | 业务用户能力 + 部门科研资料和模板 | 公共数据 + 本部门授权资料 |
| 审核专家 | 审核报告、标签、重点新闻和技术指标 | 被分配任务及授权部门数据 |
| 数据运营员 | 数据源、采集任务、清洗、标签和数据质量 | 全部科技信息数据，不默认访问私密报告正文 |
| 模板管理员 | 报告模板、导出模板、Prompt 模板 | 模板库和测试样例 |
| 系统管理员 | 用户、角色、权限、模型配置、日志、备份 | 全局管理范围 |

### 5.2 数据权限

资料、报告和任务必须同时具备以下属性：

- 所有者 `owner_id`。
- 所属部门 `dept_id`。
- 可见级别 `private / department / organization / public`。
- 授权用户/角色列表。
- 是否允许下载、导出、复制、用于模型生成。

“用户每个只能看到自己生成的报告”作为默认规则；只有用户主动共享、部门规则授权或管理员审计时，其他人才能访问。

### 5.3 用户端与后台端隔离

- 用户端采用顶部业务导航，不加载若依后台侧栏。
- 后台端采用若依 Layout，仅管理员和运营人员可访问。
- 前端隐藏菜单只是体验措施，后端所有接口仍必须执行权限校验。
- 用户访问无权限路由返回 403 页面，不能回退到后台首页。

## 6. 信息架构

### 6.1 普通用户端一级导航

为避免用户端页面重复和菜单过多，一级导航固定为六项：

1. 首页
2. 科技资讯
3. 论文资料
4. 科研工作台
5. 日报周报
6. 知识库

头像菜单提供“我的任务、我的报告、我的收藏、个人设置、退出登录”，不再额外占用一级导航。

### 6.2 管理员后台一级导航

1. 运营总览
2. 数据源管理
3. 采集任务
4. 数据治理
5. 资料与知识库
6. 报告与模板
7. 模型与 Prompt
8. 用户与权限
9. 日志与运维

若沿用若依内置系统管理、系统监控等模块，仅后台管理员可见；前端菜单名称可按业务重新包装。

## 8. 关键业务流程

### 8.1 资讯入库流程

1. 数据运营员配置来源、栏目、时间范围、关键词和频率。
2. 系统执行试采，生成字段完整性和解析预览。
3. 运营员确认规则并启用正式采集。
4. 系统保存原始数据，进行正文抽取、标准化和去重。
5. 系统生成摘要、分类和标签。
6. 低置信度或异常记录进入人工复核队列。
7. 通过质量校验后发布到用户端并更新搜索索引。
8. 所有阶段记录处理版本、时间和错误信息。

### 8.2 科研报告生成流程

1. 用户选择报告类型和模板。
2. 用户从资料篮选择内部资料、英文报告、论文、资讯或上传新资料。
3. 系统校验权限、解析状态和资料可用性。
4. 用户填写研究方向、关键词、业务场景、目标和补充要求。
5. 系统检索相关片段，生成可编辑大纲和资料覆盖提示。
6. 用户确认大纲后启动异步生成。
7. 系统逐章节生成并建立段落到来源片段的引用关系。
8. 系统执行结构、重复、指标一致性、引用和敏感信息检查。
9. 用户在线编辑或对局部提出重生成要求。
10. 用户生成概念图、思维导图或技术路线图，并编辑节点。
11. 用户保存版本，发起审核或直接导出。
12. 导出任务套用 Word/PDF 模板，生成文件并写入操作日志。

### 8.3 日报周报流程

1. 自动计划或用户手动创建任务。
2. 按日期、来源、技术方向和关键词检索候选资讯。
3. 去重并将同一事件聚合为主题。
4. 根据客户规则筛选重点内容，保持来源和业务方向覆盖。
5. 按模板栏目生成摘要、研判、热点和来源清单。
6. 用户调整内容、顺序和栏目并保存版本。
7. 导出 Word/PDF；需要时由审核人确认后发布。

## 9. 报告生成质量规则

### 9.1 必须遵守

- 生成内容只能使用用户有权限的资料。
- 事实、数据、标准、案例和外部结论应关联来源。
- 找不到证据时使用“资料中未提供/需要补充”而不是编造。
- 用户提供的技术指标优先于模型推断，修改指标需明确提示。
- 每次生成记录模型、Prompt、模板、资料版本和参数。
- 人工修改内容不得被后台自动任务静默覆盖。
- 导出前必须通过必填项、章节完整、引用和敏感信息检查。

### 9.2 建议的章节级控制参数

- 目标字数
- 写作语气
- 是否要求引用
- 最少引用数量
- 是否允许使用外部公开资料
- 是否生成表格
- 是否生成技术指标
- 是否生成年度计划
- 是否生成经费建议
- 禁止词/敏感词

## 10. 非功能需求

### 10.1 性能

- 普通列表和详情接口 P95 小于 1 秒（不含外部模型调用）。
- 统一搜索 P95 小于 2 秒，首期目标数据规模按 10 万条设计。
- 大文件解析、模型生成、翻译和导出必须异步化，不阻塞 Web 请求。
- 页面首屏采用骨架屏，长列表虚拟化或分页。

### 10.2 可用性

- 采集、解析、生成任务支持失败重试和断点恢复。
- 关键任务状态可查询，不依赖浏览器保持打开。
- 数据库、文件和配置有备份与恢复流程。
- 外部模型不可用时保留任务并提示重试，不丢失用户输入。

### 10.3 安全

- 使用若依 JWT/Bearer 鉴权和后端权限依赖。
- 密码、模型密钥和数据源凭据不得明文存储或返回前端。
- 上传文件进行类型、大小、扩展名、MIME 和恶意内容检查。
- 爬虫只访问允许的域名，防止 SSRF 和内网地址探测。
- 防止上传资料中的 Prompt Injection 直接改变系统指令。
- 日志中对手机号、邮箱、Token、密钥和敏感正文脱敏。
- 资料下载、报告导出采用一次性或短期签名 URL。

### 10.4 合规

- 保存内容来源、抓取时间、原文链接和版权状态。
- WOS、期刊和第三方网站遵守授权、robots、频率和使用条款。
- 新闻图片本地存储策略须客户确认版权和保留周期。
- 用户上传资料需确认其拥有处理和用于模型生成的权限。

### 10.5 可观察性

- API 请求链路 ID。
- 任务 ID、模型请求 ID、数据源运行 ID。
- 采集成功率、解析失败率、生成耗时、模型错误率、队列积压。
- 关键失败可配置邮件、企业微信或站内告警。

## 11. 验收清单

### 11.1 业务验收

- 用户登录后只能进入授权的用户端业务页面。

## 13. 当前代码现状与目标差距

### 13.1 当前已有原型能力

- Vue 3 + Vue Router + Pinia + Element Plus 的若依前端基础。
- FastAPI 若依后端的登录、用户、角色、菜单、权限和日志能力。
- `/portal`、`/portal/news`、`/portal/papers`、`/portal/reports` 用户端路由。
- `/pipeline/dashboard`、情报列表/详情、数据源、采集任务、报告草稿、知识库问答接口。
- `/manuscript/generate`、任务列表/详情、Markdown 导出和候选标题接口。
- 前端已有情报、数据源、任务、知识库、报告和论文生成页面骨架。

### 13.2 当前主要不足

- 管网业务数据和 manuscript 任务主要为内存模拟数据，服务重启后无法保存。
- 没有真实爬虫、试采、原始数据、清洗、去重、数据质量和搜索索引流水线。
- 没有真实文件解析、MinIO/对象存储、向量检索和引用定位。
- 报告生成是规则化 Markdown 草稿，不是基于资料的多阶段 LLM 流程。
- 尚未实现 S1/S2 模板级 Word/PDF 导出、经费表、图形编辑和版本差异。
- 日报周报缺少计划任务、模板、内容筛选、编辑、来源清单和发布流程。
- 翻译、热点分析、OCR、审核流等尚未形成正式模块。

### 13.3 建议改造顺序

1. 固化用户端信息架构和登录权限边界。
2. 将 pipeline/manuscript 内存数据改为数据库持久化。
3. 建设文件、数据源、采集、清洗和搜索基础设施。
4. 建设资料解析、向量检索和引用体系。
5. 将科研报告生成改造为模板驱动的异步任务。
6. 完成日报周报、图形和 Word/PDF 导出。
7. 最后接入热点、翻译、OCR 和自学习等增强功能。
