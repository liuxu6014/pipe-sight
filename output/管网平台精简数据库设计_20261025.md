### 默认值及更新时间的精确定义

字段字典“必填/默认”列中的默认值是业务语义，不能仅凭该列判定数据库已经配置默认表达式。`server_default` 是数据库 INSERT 省略列时生效的默认值；ORM `default` 是应用端写入补值；ORM `onupdate` 只在适用的 ORM 更新路径写值，**不等于数据库 UPDATE 触发器**，也不保证任意原生 SQL 更新会自动改变 updated_at。IDENTITY 和泛化 autoincrement 也必须分别核对。

本轮已按最终 v4/ORM/迁移与正式源库证据对齐数据库默认值和生成方式，不通过删除现有有效默认值掩盖差异；客户端更新时间机制单独记录，不虚构数据库触发器。修复前默认值、索引与 CHECK 差异保留为历史审计证据，当前修复闭环结果在对应验证章节记录。

## 一、业务边界

| 业务 | 数据库应该支持什么 | 不额外引入什么 |
| --- | --- | --- |
| 新闻资讯 | 新闻网站、公众号统一入新闻表；列表、搜索、分类筛选、正文详情 | 不为公众号另建文章主表，不建审核流程 |
| 论文 | 独立论文表；作者、期刊、DOI、真实发表日期及摘要 | 不存论文全文、不展示全文阅读，不把入库时间当论文发表时间 |
| 分类 | 管理员定义类别与提示词，大模型过滤并给每篇文章确定一个类别 | 不建多类别关联表，不再叠加“领域—主题—规则—提示词版本”多层配置 |
| 上传资料 | 保存原文件、提取文本、用户编辑文本；解析状态自动刷新、失败可重试 | 不把上传成功等同解析成功，不覆盖用户已修改的正文 |
| 生成文章/报告/简报 | 用户选择模板和资料，生成正文、编辑保存；图片模型由后台配置 | 不另建一份采集文章，不强加人工审核/发布审批 |
| 配图 | 保存实际图片文件位置、生成提示词、模型、状态；可展示、可重试 | 不把“模型支持图片输入”当成“能生成图片” |
| 周期简报 | 每天、每周指定星期、每月指定日期及时间自动生成 | 不每次读取全库直接送模型，不静默截断手工勾选 |

## 三、字段约定

- 引擎沿用 PostgreSQL。用户授权的 12 张业务表字符串主键及其关联外键已迁为 `bigint`（正式切换及接口验收完成），旧值通过完整映射迁入新编号；sys_*、框架表以及原已为 bigint 的主键保持不变。
- 业务实体主键及其引用均明确标为 `bigint`；请求幂等键、执行令牌、哈希和存储键仍为字符串，不因含 UUID 而当作实体主键。`timestamp(0)` 专指业务 created_at、updated_at 的北京时间无时区秒值；其余标为 `时间` 的运行/发表时间点仍采用 `timestamptz`。“必填”指最终业务数据；不同时间语义不可直接强转或混用。
- 表格列出的字段是规范化后的建议完整业务字段集。不默认附加审核人、审核时间、审核意见、评分、血缘、交接批次、软删除等字段。
- 业务 `created_at`、`updated_at` 由系统维护，数据库为北京时间 `timestamp(0) without time zone`，接口显示 `YYYY-MM-DD HH:mm:ss`；凡业务表已有 updated_at 而字段字典合并说明处，均遵守同一规则，不额外新增缺失字段。正文用 `text`；结构化配置及任务选材快照用 `jsonb`。独立业务实体之间使用外键；快照中的历史来源 ID 不具备数据库外键约束，明确由服务端校验，不冒充实时关联。
- 原文件和图片保存在文件系统/对象存储；表里存稳定存储键，不能只存会过期的访问 URL。文件也要备份。
- 下列新 `is_enabled` 为布尔值；现有若依基础表的状态编码不在本方案中强行改写。

### 字段统一规则（本轮修订）

| 项目 | 统一规则 | 示例 |
| --- | --- | --- |
| 表名 | 业务表小写复数、最多两个英文单词；若依基础表与框架表例外 | news_articles、papers、basket_items；sys_user_role 保留原若依物理名 |

“字段简洁”不是所有字段限制两个单词：image_model_id、password_updated_at 等保留必要含义；不用难懂缩写代替语义。is_enabled 是启停布尔，status 是任务状态枚举，两者不混用。分类失败不能以 category_id 为空推断为人工审核失败。

PostgreSQL 实现约定：业务审计时间默认值为 date_trunc('second', CURRENT_TIMESTAMP AT TIME ZONE 'Asia/Shanghai')；updated_at 由统一应用写入逻辑维护，未额外创建数据库 UPDATE 触发器，不照搬 MySQL 的 ON UPDATE CURRENT_TIMESTAMP、DATETIME、AUTO_INCREMENT。基础表历史 created_by、updated_by 仍是原账号文本，不因改名就当成 sys_user.id 外键；新业务表不自动增添这些字段。若依表保留原时间类型和默认值，不受本轮业务时间统一影响。

### 3.1 `news_articles`：新闻资讯主表

| 字段 | 类型 | 必填/默认 | 说明/关联 |
| --- | --- | --- | --- |
| id | bigint | 必填，主键 | 共享序列分配的新文章 ID，保留旧值映射 |
| source_id | bigint | 必填 | 外键 → `data_sources.id`，ON DELETE RESTRICT；新闻网站/公众号类型从来源表取得 |
| title | varchar(1000) | 必填 | 文章标题 |
| url | text | 必填 | 原文地址；保存规范化结果用于去重 |
| author | text | 可空 | 原作者；未知就空，不填来源网站冒充作者 |
| published_at | 时间 | 可空 | 原文真实发布时间，显示到秒；未知不填入库时间 |
| content | text | 可空 | 原文正文；抓取未获得正文时允许空 |
| content_zh | text | 可空 | 中文正文/译文；原文已经中文时可空，展示回退 `content` |
| category_id | bigint | 可空 | 外键 → `categories.id`；每篇文章只对应一个类别，未分类/未命中时为空；删除类别采用 RESTRICT |

| created_at | timestamp(0) | 必填 | 入库时间 |

类别通过 category_id 直接关联 categories；一个字段只保存一个类别 ID，不存数组或逗号分隔值。未分类或未命中时可空；分类成功后只对应一个类别。类别名称、提示词只维护在类别表中。来源名称通过来源表获取，不重复维护两份可编辑名称。

约束：规范化 url 去重；来源先建档再入文章，source_id 必填。新闻表不再重复保存 type，网站/公众号筛选通过 data_sources.type 进行；服务端仅允许关联 website 或 wechat 来源。来源以停用代替直接删除，已被新闻引用的来源不得删除，不因来源配置清理而丢失来源类型。

### 3.2 `papers`：论文主表

| 字段 | 类型 | 必填/默认 | 说明/关联 |
| --- | --- | --- | --- |
| id | bigint | 必填，主键 | 共享序列分配的新论文 ID，保留旧值映射 |
| source_id | bigint | 可空 | 外键 → `data_sources.id` |
| title | varchar(1000) | 必填 | 原始标题 |
| title_zh | varchar(1000) | 可空 | 中文标题；与原始标题相同则无需重复显示 |
| url | text | 可空 | 论文来源页面地址；DOI、此 URL 至少有一个；不表示平台拥有全文 |
| doi | varchar(255) | 可空 | 规范化 DOI，不带 `https://doi.org/` 前缀 |
| authors | text | 可空 | 原始作者名单；当前无作者实体管理需求，不额外建作者表 |
| journal | varchar(255) | 可空 | 期刊/会议名称 |
| published_date | varchar(10) | 可空 | 论文发表日期；ISO 部分日期：`2024`、`2024-06`、`2024-06-18`；严格校验合法日期 |
| abstract | text | 可空 | 原文摘要 |
| abstract_zh | text | 可空 | 中文摘要 |
| category_id | bigint | 可空 | 外键 → `categories.id`；每篇文章只对应一个类别，未分类/未命中时为空；删除类别采用 RESTRICT |
| is_pushed | boolean | 必填，false | 是否成功推送；同样不是审核状态 |
| created_at | timestamp(0) | 必填 | 平台入库时间 |
| updated_at | timestamp(0) | 必填 | 更新时间 |

DOI 非空时唯一。没有 DOI 时，规范化 url 非空且唯一。published_date 表示真实论文发表日期；仅有年份时不伪造某月某日。按发表时间排序可用部分日期生成的排序表达式，日期区间查询以真实精度作区间相交判断，不能拿 created_at 替代。

论文没有全文，本表不设 content、content_zh 或全文存储地址等替代字段，不通过 JSON 或资源表变相保存论文全文。详情仅展示文献信息及摘要，可通过 DOI/url 跳转来源；分类和生成选材仅使用标题、文献信息和可得摘要，不声称已读取全文。历史代码如有全文预览或本地文件，后续实施时先备份、核对引用后退出该链路，不在本轮删除。

### 3.3 `categories`：类别与提示词

| 字段 | 类型 | 必填/默认 | 说明/关联 |
| --- | --- | --- | --- |
| id | bigint | 必填，主键 | 类别 ID |
| name | varchar(100) | 必填，唯一 | 管理员设置的类别名，如管网安全、应力监测 |
| prompt | text | 必填 | 管理员编写的过滤、分类标准，明确什么内容属于该类 |
| model_id | bigint | 启用分类时必填 | 外键 → `ai_models.id`；后台直接为类别选择文本模型，无路由中间表 |
| applies_to | varchar(16) | 必填，all | `news`、`paper`、`all` |
| is_enabled | boolean | 必填，true | 是否参加后续分类 |
| sort_order | integer | 必填，0 | 前台分类排序 |
| created_at | timestamp(0) | 必填 | 创建时间 |
| updated_at | timestamp(0) | 必填 | 最近修改时间 |

提示词修改只影响后续处理；历史文章重分类须明确触发，不删除旧类别就自动重跑全库。停用类别不抹掉历史归类。

单类别规则：news_articles.category_id 和 papers.category_id 均直接引用 categories.id，每篇文章最多保存一个类别。两个字段都不加 UNIQUE，因为同一个类别可以对应多篇文章。分类提示词要求模型在适用且启用的类别中选择一个最匹配类别，或明确返回未命中；返回多个类别视为无效输出进行重试/报错，不随机取第一个。

写入前由服务端检查类别已启用且 applies_to 适合该文章类型，数据库外键保证类别存在。重分类只更新文章上的 category_id，不新增文章。类别停用不清除历史关联；已被文章引用的类别禁止直接删除（ON DELETE RESTRICT），须先明确迁移或清空关联。

**过滤不命中 ≠ 内容未通过审核。** 建议仍保存可展示原文，只是不进入该类别的生成候选；如果业务要求“不命中任何类别就不展示/不入库”，需单独确认，不能擅自丢弃数据。

分类失败不生成“未分类成功”的假关联，由任务队列记录失败原因及重试；本基准不再建一份文章处理收件箱。部署应提供持久化队列与超时重试，否则不能声称分类任务可靠。

| size | bigint | 必填 | 原文件字节数，非负 |
| hash | varchar(64) | 必填 | SHA-256；同一用户可用于重复上传提示 |
| extracted_text | text | 可空 | 系统提取结果，解析重试只更新此字段 |

上传成功即提示“已保存到资料库”；解析状态单独展示。扫描、大小、类型、解压限制仍须服务端执行，取消审核表并不等于取消文件安全校验。原有隔离文件不能在迁移中直接变成可用文件。

实施补充确认：用户允许先完成迁移、后在管理员界面配置模型。ai_models 一张表同时登记文本和图片生成模型；模板的 model_id/image_model_id 在未配置阶段允许为空，模型未配置不影响登录、浏览或选择模板。提交正文生成及启用自动简报前校验文本模型；请求配图时再校验图片生成模型，缺少时明确提示，不自动创建假配置。真正的模型生成验收须待管理员配置后完成。

### 3.9 `generation_tasks`：生成任务

| 字段 | 类型 | 必填/默认 | 说明/关联 |
| --- | --- | --- | --- |
| id | bigint | 必填，主键 | 每次生成/明确重跑的任务 ID |
| report_id | bigint | 必填 | 外键 → `reports.id`，一个成果可多次生成 |
| schedule_id | bigint | 可空 | 外键 → `digest_schedules.id`，手动任务为空 |
| request_id | varchar(128) | 必填，唯一 | 全局幂等键；手动提交用随机 UUID，周期任务用计划 ID + 本轮触发时刻 |
| status | varchar(16) | 必填，queued | `queued`、`running`、`completed`、`failed`、`cancelled` |
| progress | smallint | 必填，0 | 0～100 |
| config_snapshot | jsonb | 必填 | 模板正文、提示词、模型标识、参数、筛选条件、成果起始版本及用户确认的冻结大纲；不含密钥。本轮大纲实际使用修复待验收 |
| materials | jsonb | 必填，[] | 最多 50 条实际选材的有序只读快照；每项含 type、id、title、content、source，不再单建选材表 |
| result_content | text | 可空 | 此任务生成的原始正文，和用户当前编辑正文区分 |
| error | text | 可空 | 失败原因 |
| attempts | integer | 必填，0 | 自动重试次数，非负 |
| lease_expires_at | 时间 | 可空 | 执行租约；过期才允许抢占恢复，提交结果须校验当前执行令牌 |
| execution_token | varchar(64) | 可空 | 每次执行尝试唯一令牌，防止旧执行器回写新尝试 |
| started_at | 时间 | 可空 | 开始时间 |
| finished_at | 时间 | 可空 | 完成/失败/取消时间 |
| created_at | timestamp(0) | 必填 | 提交时间 |
| updated_at | timestamp(0) | 必填 | 状态更新时间 |

任务原子认领、幂等入队、失败重试都属于执行可靠性，不是审核体系。取消任务不删除已有成果。手动勾选最多 50 篇资料，前后端一致校验，超出明确拒绝而不是截掉；正文总量还需按模型上下文预算校验，超限提示缩减或分批提炼。

任务不保存重复的 user_id，查询和权限均通过 report_id → reports.user_id 判断。首次创建成果和任务须在同一事务内完成；全局 request_id 冲突时回滚本次空成果并按上述幂等规则处理，不能留下重复空草稿。任务的 config_snapshot 只保存配置和版本，materials 只保存实际选材，不在两个 JSON 中重复复制整段材料正文。

选材直接保存在 materials 字段，示例结构为 `[{"type":"paper","id":"论文ID","title":"实际标题","content":"本次使用的论文摘要","source":{"doi":"原DOI"}}]`。这里的 content 是任务统一输入字段，不是 papers 表的全文字段。type 仅允许 article、paper、file；同一 type + id 不重复；数组顺序就是选材顺序。论文只取摘要及文献信息，新闻取可用正文；文件使用 edited_text 非空值优先的规则，不能只存 ID、生成时才读取后来已修改的正文。

服务端在提交事务中按真实表加载资料、检查存在性和所有权、数量及正文预算，再构建快照；不信任前端传来的正文或权限。数据库可 CHECK 为数组且长度不超过 50；逐项结构、唯一性、权限由服务端严格校验。提交后快照不可由普通编辑接口修改，自动重试沿用快照；重新选材创建新任务。

这是任务输入的历史副本，不是实时外键关联；源资料修改/删除不会自动更新快照，也没有数据库级 RESTRICT。历史引用展示以快照为准，跳转原资料时重新判断存在性及访问权限。确需彻底删除用户资料时，必须一并查找并清理相关快照，不能仅删原文件后声称所有副本已删除。未来若确有高频反向引用查询或逐条选材编辑需求，再评估拆表，不提前建设。

### 3.10 `report_assets`：图片及导出资源

| 字段 | 类型 | 必填/默认 | 说明/关联 |
| --- | --- | --- | --- |
| id | bigint | 必填，主键 | 资源 ID |
| report_id | bigint | 必填 | 外键 → `reports.id` |
| task_id | bigint | 可空 | 与 report_id 组成复合外键 → generation_tasks.(id, report_id)，绑定生成尝试；独立导出可空，不另建重复的单列任务外键 |
| type | varchar(16) | 必填 | `image`、`export` |
| storage_key | text | 成功后必填 | 文件稳定存储键；queued 时允许空 |
| mime_type | varchar(128) | 必填 | 提交时选定的输出类型，如 image/png、application/pdf；成功后核对实际文件，不另存重复的 format 字段 |
| prompt | text | 可空 | 图片实际提示词；导出文件为空 |
| model_id | bigint | 可空 | 外键 → `ai_models.id`；导出无需模型 |
| config_snapshot | jsonb | 必填，{} | 模型代码/提供方、配图参数，或导出时正文版本/内容快照，不含密钥 |
| position | varchar(100) | 可空 | 图片所在章节/占位符 |
| status | varchar(16) | 必填，queued | `queued`、`running`、`completed`、`failed` |
| error | text | 可空 | 配图或导出失败原因 |
| created_at | timestamp(0) | 必填 | 创建时间 |
| updated_at | timestamp(0) | 必填 | 更新时间 |

正文通过资源 id 解析出的受控文件地址；链接访问时校验成果权限。图片失败可独立重试，不重新生成全部正文。后台图片模型未配置时明确提示不可用，不展示假图或静默跳过。资源子任务沿用持久化队列的重试/幂等机制；重试前检查是否已成功落盘，避免重复收费。

资源的 report_id 不能全部由 task_id 替代，因为独立导出允许没有生成任务。为避免两个字段指向不同成果，在 generation_tasks 上声明 UNIQUE(id, report_id)，并以 report_assets.(task_id, report_id) → generation_tasks.(id, report_id) 建复合外键（MATCH SIMPLE，ON DELETE RESTRICT）；task_id 为空时仍由 report_id 的单列外键保证成果存在。这里保留的是有独立导出需求的条件性字段，不再新增中间关系表。

本表由现有 report_exports 改造成图片/导出资源表，不再并存一张单独的导出表。之所以不压成 reports 上的 image_url 单字段，是因为一份成果确实可包含多张图，而且每张图要独立记录生成、失败、重试和文件；压成一个字段会丢掉这些已要求的操作能力。资源用 report_id、task_id 直接关联，不再加“成果—资源”中间表。

不新增全局“文件元数据大表”。上传原文件归资料库表，生成资源归本表；本表不用于论文全文或原文图表存储。

### 3.11 `digest_schedules`：自动生成计划

| 字段 | 类型 | 必填/默认 | 说明/关联 |
| --- | --- | --- | --- |
| id | bigint | 必填，主键 | 计划 ID |
| user_id | bigint | 必填 | 外键 → `sys_user.id` |
| name | varchar(255) | 必填 | 计划名 |
| template_id | bigint | 必填 | 外键 → `templates.id` |
| frequency | varchar(16) | 必填 | `daily`、`weekly`、`monthly` |
| weekday | smallint | 条件必填 | 每周：0～6，周一到周日；其他周期为空 |
| month_day | smallint | 条件必填 | 每月：1～31；其他周期为空 |
| run_time | time | 必填 | 当地执行时分秒 |
| timezone | varchar(64) | 必填，Asia/Shanghai | 调度时区 |
| selection_config | jsonb | 必填 | 日期窗口、类别、来源、关键词、去重规则及自动选材上限 |
| generation_config | jsonb | 必填，{} | 摘要长度、配图等生成设置 |
| is_enabled | boolean | 必填，true | 是否启用 |
| next_run_at | 时间 | 启用时必填 | 下次触发时间，便于索引调度 |
| last_run_at | timestamp(0) without time zone | 可空，无默认值 | 最近派发检查时间，北京时间精确到秒；旧记录不回填 |
| last_status | varchar(16) | 可空，无默认值 | queued 入队、no_data 无匹配、skipped 节假日跳过、failed 派发失败；生成状态读取关联任务 |
| last_error | text | 可空，无默认值 | 脱敏后的派发失败原因；本次成功或跳过清空，不保存内部堆栈 |
| created_at | timestamp(0) | 必填 | 创建时间 |
| updated_at | timestamp(0) | 必填 | 更新时间 |

每月 31 日遇到短月按当月末日执行，下月仍按 31 日计算。每次先按条件筛选、去重、排序，再按显式配置选至多 50 篇；记录候选数量及取材策略到任务快照。自动任务允许按配置取前 N 篇，与静默截断用户手工选择是两回事。没有可用资料则记录调度结果，不伪造空简报。

调度认领与 next_run_at 推进应事务化；用 `schedule:计划ID:本次触发的UTC时刻` 生成全局幂等 request_id，唯一约束保证同一计划同一轮不重复生成。手动提交用 `manual:随机UUID`，避免两种来源冲突。命中同一 request_id 时须校验成果所有者和请求内容是否一致：相同请求返回原任务，不同内容拒绝；不得返回其他用户的任务或覆盖旧任务。现有节假日策略如继续启用，纳入 selection_config/调度策略并保持原语义。

派发成功、无匹配、节假日跳过与摘要更新在同一事务内提交；派发失败回滚本轮任务创建，保留原调度游标并保存失败原因。已生成任务的历史计划只能停用，不删除关联。`generation_tasks(schedule_id,id)` 增加普通索引用于批量查询每条计划最近任务，接口按计划所有者与报告所有者同时检查权限。

### 3.13 `collection_runs`：采集运行、停止与失败重试

| 字段 | 类型 | 必填/默认 | 说明/关联 |
| --- | --- | --- | --- |
| id | bigint | 必填，主键 | 共享序列分配的新运行 ID，旧 run_id 建立映射；每次实际执行一条记录 |
| source_id | bigint | 必填 | 外键 → `data_sources.id`，ON DELETE RESTRICT；一个来源可有多次历史运行 |
| parent_id | bigint | 可空 | 与 source_id 组成复合外键 → collection_runs.(id, source_id)；只对重试填上一次失败运行 ID，原始任务为空 |
| trigger_type | varchar(16) | 必填 | `manual` 手动、`schedule` 定时、`retry` 失败重试 |
| request_id | varchar(128) | 必填，唯一 | 本次采集入队幂等键，重复点击/调度不创建重复运行 |
| status | varchar(16) | 必填，queued | `queued`、`running`、`stopping`、`success`、`failed`、`cancelled`；stopping 表示已请求停止但尚未确认退出 |

| failed_count | integer | 必填，0 | 本次处理失败的候选条目数；可部分成功，状态按下文规则确定 |
| error | text | 可空 | 本次失败或执行器异常的简短原因，去除密钥、Cookie 和堆栈 |

采集权限由现有管理员角色与接口权限控制，启停/停止/重试操作复用 sys_oper_log；不为此再建爬虫管理员、停止指令、重试事件表，也不重复存用户或来源名称。历史旧运行字段按本节映射：run_id → id、error_message → error、checkpoint_json → checkpoint、create_time/update_time → created_at/updated_at；inserted_count/updated_count 汇成 saved_count 前须核对旧统计口径。旧 handoff_* 属于已计划退出的外部交接体系，先归档历史、迁完依赖再移除，不混入本次爬虫状态。

#### 管理操作及状态变化

| 操作 | 更新位置 | 明确行为 |
| --- | --- | --- |
| 启用来源 | data_sources.is_enabled=true | cron 非空则按时区计算 next_run_at；cron 为空只允许手动。启用本身不立即爬取，也不复活以前取消的任务 |
| 停用来源 | is_enabled=false，next_run_at=NULL | 阻止新建任务及 queued 任务启动；已排队记录转 cancelled 并填 stop_requested_at/finished_at。已开始的 running 不自动假装停止，如需中断另发本次停止请求 |
| 立即采集 | 新建 queued 运行，available_at=当前时间 | 来源须已启用；同一来源已有 queued/running/stopping 时返回该活跃运行，不并发启动第二次 |
| 定时采集 | 扫描来源 next_run_at，原子推进下一时刻并提交 queued 运行 | 幂等键取 `schedule:来源ID:计划触发UTC时刻`；已有活跃运行则跳过本轮、不累计无限队列，并记录运维日志 |
| 停止排队任务 | queued → cancelled | 填 stop_requested_at、finished_at；不得再被认领，没有工作进程需要等待 |
| 停止正在采集 | running → stopping，填 stop_requested_at | 执行器在请求间、分页间及每批写入前检查并退出；确认结束后才 stopping → cancelled。按钮返回“已请求停止”，不是“已停止” |
| 重复停止/停止已结束任务 | 不改终态 | stopping 返回“正在停止”；success/failed/cancelled 返回当前结果，不伪造一次取消 |
| 失败重试 | 保留 failed 原记录，创建 trigger_type=retry 的新 queued 运行 | parent_id 指向原失败记录；配置使用原 config_snapshot；原记录的错误和计数不清空、不覆盖 |

正常状态为 queued → running → success/failed；停止路径如上，success/failed/cancelled 为终态，不原地重置为 queued。running 中有条目失败时继续处理可恢复条目，但结束置 failed、保留已保存结果与失败数；fetched_count=0 且来源确无新内容可置 success，不伪造一条新文章。自动重试是否开启、上限（例如最多 3 次额外重试）及退避秒数显式配置在 config.retry，冻结到运行快照；没有配置时默认不自动重试，管理员仍可明确点击重试。

#### 失败恢复、并发与停止安全

- 来源认领与启停锁定同一 data_sources 行，入队/启动前重新检查 is_enabled；不能先读开关、稍后绕过停用入队。网络请求期间不长期持有数据库锁。
- 同一 source_id 在 status IN ('queued','running','stopping') 时建部分唯一索引，保证只有一条活跃运行；queued 只有 available_at ≤ 当前时间才可认领，认领和状态/令牌/租约更新必须原子完成。
- 声明 UNIQUE(id, source_id)，重试使用 (parent_id, source_id) 复合自外键，MATCH SIMPLE、ON DELETE RESTRICT，防止跨来源重试；CHECK parent_id IS NULL 或 parent_id <> id。trigger_type=retry 必须有 parent_id，其他触发类型必须为空，条件采用显式 CHECK。
- parent_id 非空时再建部分唯一索引，保证一条失败记录最多一个直接重试子记录；重复点击返回已创建子记录。再次失败时重试最新失败子记录，递归计数检查自动重试上限，不再存一份冗余 attempts。父运行须已存在、同来源且状态 failed；parent_id/source_id/创建时配置不可后改，服务端拒绝自指和循环链。
- 重试先检查来源仍启用、采集器可用且原错误适合重试；管理员已停止或来源已停用时不自动创建新重试。重试排队的退避时刻写 available_at，重启服务仍可恢复，不依赖进程内 sleep。
- 重试只保存本次的计数，不把父计数重复累计。checkpoint 仅在采集器支持恢复时沿用，否则从入口重跑；按规范化 URL/DOI 幂等写入 news_articles/papers，避免已经成功入库的文章重复插入。端点临时故障等会话问题可重试，配置或凭证错误须先修复；改了采集规则需要新建手动运行，不静默改写旧快照。
- 断点不能跨过未处理成功的失败条目后把它遗忘：适配器要么停在首个未解决边界，要么在同一个 checkpoint 保存受限的失败条目标识并优先补采；不支持可靠续跑时从头幂等重跑。checkpoint 不另存材料正文，错误条目标识超过上限时退回从头重跑，不静默丢掉失败项。
- 已创建但后来取消的重试子记录不删除、不原地重开；重复点击仍返回该记录。管理员确认需要重新采集时创建新的 manual 运行；如子记录再次失败，则对最新 failed 子记录重试，不能绕开父记录唯一约束再生成第二个直接子记录。
- 停止请求要持久化；已提交的文章不回滚，正在进行的网络请求须受连接/读取/总超时限制，执行器不再发新请求、不再提交新批次，完成资源释放后回写 cancelled 并清理令牌/租约。
- 每批入库及计数/断点更新放同一事务，核对当前 status=running、有效 execution_token 与未过期租约，过期令牌不得写入。认领后的崩溃/超时不能长期显示 running：恢复器先隔离旧令牌，再记 failed 和异常原因，按显式策略重试；有停止请求则不自动重试。stopping 的取消确认必须来自执行器应答或管理员确认已隔离/停止工作进程，失联不能直接声称所有外部请求已经终止。
- 管理页定时读取活跃记录直到终态；由适配器和执行器真正实现协作取消、超时、心跳与幂等，不把“数据库字段存在”冒充“停止功能已经实现”。停止/重试与结束竞态使用状态条件更新，已提交的终态优先，不反转历史结果。

#### 调度边界与约束

data_sources.cron 负责各来源的采集周期，现有 sys_job/APScheduler 只需负责唤醒扫描器/执行器，不为每个来源再维护一份相同周期，也不额外建采集计划表。collection_runs 不设 scheduler_job_id 或 job_id：业务追溯用 source_id、trigger_type、request_id，旧框架任务编号如需历史保留可归档在旧配置快照，不再强加新的运行外键。

来源 cron 非空才允许 next_run_at；is_enabled=false 时 next_run_at 必须为空。cron 与 IANA 时区由服务端严格解析，统一以 UTC 时间点入库，夏令时歧义遵循明确调度策略；表达式或时区修改后重新计算，不补排无限历史任务。collection_runs 的计数 CHECK 非负，saved_count + failed_count ≤ fetched_count（同一候选在本次只计一次）；成功时 failed_count=0；queued 的 started_at/finished_at 为空；running/stopping 有 started_at、无 finished_at；终态必须有 finished_at；stopping/cancelled 必须有 stop_requested_at；时间先后合法，所有非重试运行 parent_id 为 NULL。终态清空租约和执行令牌，队列消息可重复投递，但已结束记录不会重复执行。

运行字段边界：queued 不持有 execution_token/lease_expires_at；running 必须同时具备两者且 stop_requested_at 为空；stopping 必须有停止请求和 started_at。执行器失联、令牌已被隔离时允许 stopping 的令牌/租约清空，但 finished_at 仍为空，等待退出确认；不得为了满足字段约束伪造有效租约。failed 必须有非空 error，success 清空 error；未执行就取消可没有 started_at。先将 created_at 经 AT TIME ZONE 'Asia/Shanghai' 解释为时间点，再检查其不晚于 available_at、started_at、finished_at、stop_requested_at；finished_at 仍不得早于 started_at，不依赖数据库会话时区。CHECK 只校验行内条件，父记录必须 failed、配置不可变和合法状态迁移仍需服务端事务校验，不声称自外键能验证这些跨行规则。

来源已被运行引用时不能硬删；停用不清空历史。失败父记录被重试子记录引用时 RESTRICT，清理须按保留期限整体归档/处理链，不删除父行留下悬空关系。来源改名、调整配置不回写历史快照；统计信息与最近状态从运行记录获取，不把正文复制进运行表。

| report_id | bigint | 必填 | reports.id；成果删除时级联删除历史 |
| version | integer | 必填，至少 1 | 成果历史版本号 |
| title | varchar(1000) | 必填 | 此版本标题 |
| content | text | 必填 | 此版本正文 |
| sections | jsonb | 必填，[] | 此版本结构化章节快照 |
| citations | jsonb | 必填，[] | 此版本引用快照 |
| quality_issues | jsonb | 必填，[] | 自动质量提示快照，不是人工审批记录 |
| model_snapshot | jsonb | 必填，{} | 模型标识与参数快照，不含凭证 |
| source | varchar(32) | 必填，manual | 版本来源，如手动编辑、生成、恢复 |
| operator_id | bigint | 可空 | sys_user.id；用户删除后置空 |
| operator_name | varchar(64) | 必填，空字符串 | 当时操作者名称快照 |
| created_at | timestamp(0) | 必填 | 版本保存北京时间，无时区，精确到秒 |
