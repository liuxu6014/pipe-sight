# 新闻处理服务测试框架文档

## 概述

本文档描述了 `app.intelligence.processing` 新闻处理 Worker 的测试框架，包括单元测试、集成测试和端到端测试。测试框架基于 `pytest` 和
`pytest-asyncio`，用于测试系统的各个部分和整体功能。

## 测试框架结构

测试框架分为以下几个主要部分：

```
backend/tests/intelligence/processing/
├── conftest.py               # Worker 测试配置和 fixture
├── unit/                     # 单元测试
│   ├── __init__.py
│   ├── test_news_processor_app.py
│   ├── test_services/         # 服务测试
│   ├── test_processors/       # 处理器测试
│   ├── test_domain/           # 领域处理器测试
│   ├── test_db/               # 数据库组件测试
│   └── test_utils/            # 工具函数测试
├── integration/              # 集成测试
│   ├── __init__.py
│   ├── test_processor_flow.py
│   └── test_service_integration.py
└── e2e/                      # 端到端测试
    ├── __init__.py
    └── test_end_to_end.py
```

## 测试类型

### 单元测试

单元测试专注于测试系统的独立组件，例如类、函数或方法。每个组件都应该被独立测试，不依赖于其他组件的实现。

主要测试内容包括：

1. **服务组件测试**：测试 Kafka、PostgreSQL、Redis 等服务组件的功能。
2. **处理器测试**：测试新闻处理器的功能。
3. **领域处理器测试**：测试特定领域（如政治、科技等）处理器的功能。
4. **数据库组件测试**：测试数据库访问层的功能。
5. **工具函数测试**：测试各种工具函数的功能。

### 集成测试

集成测试专注于测试多个组件之间的协作，确保它们能够正确地一起工作。

主要测试内容包括：

1. **处理器流程测试**：测试新闻从输入到处理完成的整个流程。
2. **服务集成测试**：测试多个服务组件之间的协作。

### 端到端测试

端到端测试专注于测试整个系统的功能，从输入到输出的全部流程。

主要测试内容包括：

1. **完整流程测试**：测试从Kafka消费消息、处理新闻到存储结果的全过程。
2. **模拟外部服务的测试**：使用模拟组件测试系统的端到端功能。

## 测试工具和库

测试框架使用以下工具和库：

1. **pytest**：Python测试框架
2. **pytest-asyncio**：异步测试支持
3. **pytest-cov**：代码覆盖率报告
4. **unittest.mock**：模拟对象库

## 测试fixtures

测试框架提供了以下全局fixtures：

1. **event_loop**：用于异步测试的事件循环
2. **mock_redis_client**：Redis客户端的模拟实现
3. **mock_postgres_client**：PostgreSQL 客户端的模拟实现
4. **mock_kafka_service**：Kafka服务的模拟实现
5. **mock_news_processor_manager**：新闻处理器管理器的模拟实现
6. **sample_news**：样例新闻数据

## 测试执行

### 运行所有测试

```bash
cd backend
uv run pytest tests/intelligence/processing -q
```

### 运行特定类型的测试

```bash
# 运行单元测试
cd backend
uv run pytest tests/intelligence/processing/unit -q

# 运行集成测试
uv run pytest tests/intelligence/processing/integration -q

# 运行端到端测试
uv run pytest tests/intelligence/processing/e2e -q
```

### 生成代码覆盖率报告

```bash
cd backend
uv run pytest tests/intelligence/processing --cov=app.intelligence.processing
```

## 测试编写指南

### 单元测试编写指南

1. 每个测试函数应该只测试一个功能点
2. 使用`pytest.mark.asyncio`装饰异步测试函数
3. 使用模拟对象替代外部依赖
4. 测试函数命名应遵循`test_[被测组件]_[测试场景]`的格式

示例：

```python
@pytest.mark.asyncio
async def test_kafka_service_consume_messages():
    """测试Kafka服务消费消息功能"""
    # 测试代码
```

### 集成测试编写指南

1. 集成测试应该测试多个组件之间的协作
2. 可以使用一部分真实组件和一部分模拟组件
3. 测试函数命名应遵循`test_[被测流程]`的格式

示例：

```python
@pytest.mark.asyncio
async def test_news_processing_flow():
    """测试新闻处理流程"""
    # 测试代码
```

### 端到端测试编写指南

1. 端到端测试应该测试整个系统的功能
2. 可以完全使用模拟组件，也可以使用真实组件
3. 测试函数命名应遵循`test_[被测场景]`的格式

示例：

```python
@pytest.mark.asyncio
async def test_full_news_processing_pipeline():
    """测试完整的新闻处理流程"""
    # 测试代码
```

## 持续集成

测试框架应该与CI/CD流程集成，确保每次代码变更都会运行测试。

示例CI配置（GitHub Actions）：

```yaml
name: Tests

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - name: Set up Python
        uses: actions/setup-python@v2
        with:
          python-version: '3.10'
      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install uv
          uv sync --frozen
      - name: Run tests
        run: |
          uv run pytest tests/intelligence/processing --cov=app.intelligence.processing
      - name: Upload coverage report
        uses: codecov/codecov-action@v1
```

## 常见问题

### 测试执行速度慢

可能的解决方案：

- 使用`pytest-xdist`并行运行测试
- 减少测试中的等待时间
- 使用更多的模拟对象代替真实服务

### 测试失败不稳定

可能的解决方案：

- 检查测试是否依赖于外部服务的状态
- 确保每个测试在执行前重置测试环境
- 增加测试中的重试机制

### 代码覆盖率低

可能的解决方案：

- 识别未被测试的代码区域
- 为这些区域添加专门的测试
- 设置代码覆盖率目标并在CI中强制执行
